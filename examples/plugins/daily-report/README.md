# 工作区日报自动化示例

后台入口分页读取最多 200 个可完成事件及最近 20 篇文档，生成包含任务和文档引用的 Markdown。每次运行用独立运行 ID 命名，保留同一天已有日报和用户编辑。文件名日期取调度时间的 UTC 日期。

在公共核心仓库执行：

```sh
npm run plugin -- pack examples/plugins/daily-report
```

将生成的包导入支持自动化的在线工作区。共享插件设置可配置 `folder`（默认 `日报`）；输出必须是普通工作区路径。

在线工作区所有者打开「插件 → 后台自动化 → 新建后台任务」，选择「工作区日报」插件和「生成工作区日报」入口，核对权限后保存授权。可点击「运行一次」，或选择按间隔执行并填写 `1440` 分钟。间隔从配置时刻开始计算；服务恢复后仅补入最近一次到期，不逐次补跑。部署管理员可配置外部调度唤醒休眠 API，执行时间可能因检查间隔和启动而延迟。运行记录显示生成的文档路径与任务统计，结果不确定时先核对已有日报。宿主任务 API 与唤醒配置见在线产品文档。包导入和前台启用不会创建后台任务；本地桌面与浏览器演示不运行此后台入口。

示例不调用外部网络或 AI 服务，不需要密钥。它生成工作区当前状态的汇总，不对文档正文进行语义总结。SDK、授权边界和限制见[插件开发文档](../../../docs/plugins.md#云端自动化入口)。

也可在此任务的「Webhook」区域生成触发凭据，由外部服务发送 JSON 请求触发日报。示例忽略外部事件正文，仍按共享的 `folder` 设置生成文档；第三方重复投递应沿用相同 `Idempotency-Key`，避免同一事件重复生成日报。触发凭据与插件服务连接密钥不同，只允许触发这个后台任务。
