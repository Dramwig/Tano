# 架構

[English](../architecture.md) | [简体中文](../zh/architecture.md) | 繁體中文 | [日本語](../ja/architecture.md) | [Español](../es/architecture.md) | [Deutsch](../de/architecture.md) | [文件目錄](README.md)

Vue 工作台透過文件 store 使用 `WorkspaceAdapter`。桌面配接器呼叫由 `tano-native` 實作的 Tauri IPC 命令。瀏覽器示範使用獨立的瀏覽器儲存配接器。`configureWorkbench(pinia, runtime)` 為每個工作台執行個體繫結一個執行環境。

```text
Vue workbench -> document store -> WorkspaceAdapter -> Tauri IPC -> tano-native
```

Markdown 檔案是內容的權威來源。編輯器與無介面的編解碼器共用同一套 Markdown 結構描述。編輯器透過 `EditorExtension` 接收宿主提供的功能，讓編輯、儲存及傳輸各自獨立。

每次儲存都會以基準雜湊比對檔案。互不重疊的外部變更可以合併，重疊的變更會保留兩個版本供審閱。若其他程序未與 Tano 協調，最後一次雜湊檢查到原子取代之間仍有短暫的競爭窗口。

工作區身分獨立於檔案路徑。工作區 UUID、檔案短 ID 及保留的 ID 隨 `.tano/identities.json` 攜帶。物件、關係和規則也位於 `.tano/`。SQLite 索引、草稿與工作階段狀態保存在工作區之外的應用程式資料中。Tano 不會跟隨指向所選工作區以外的符號連結。

## 區塊樹

文件、引言、提示區塊、可摺疊區塊，以及分頁或欄面板，都包含有順序的子區塊。容器可遞迴容納段落、表格、清單、引言、提示區塊、可摺疊區塊或分頁與欄。清單與表格保留既有的內部結構，移動時以完整區塊為單位。摺疊標題是節點的屬性。提示區塊的 `[!TYPE]` 標記是容器標頭，緊接在它後面的文字是獨立的正文區塊。資料仍以 Markdown 儲存。引言和提示區塊使用 `>` 前綴，可摺疊區塊使用成對的 `<details>` 與 `<summary>` 標記，分頁及欄使用可巢狀的容器圍欄。既有內容可直接使用這些功能，無需遷移或額外的儲存空間。

自訂提示區塊使用 `> [!CUSTOM:💡]`，後面接帶引言前綴的正文區塊。`[!CUSTOM]` 預設顯示燈泡圖示，`[!CUSTOM:icon:star]` 選用內建圖示，`[!CUSTOM:none]` 則移除圖示。宿主提供共用的表情符號和圖示選擇器，編輯器透過可復原的 Markdown 操作更新標頭。圖示可離線使用，無需應用程式資料庫。未知的提示類型會顯示為一般引言，停用提示區塊功能則會顯示原始文字。

多欄版面由並排的區塊容器構成。面板標題保留在原始碼中以維持相容性，介面會直接顯示欄內容。將區塊拖曳到另一區塊的左側或右側邊緣時，會出現垂直對齊線。放開後會建立多欄版面，若目標已在欄內，則會在該欄旁新增一欄。拖放到頂端或底端仍會垂直排序。移動或刪除欄中的最後一個區塊會移除空欄，只剩一欄時會將其展開為一般區塊。建立、清理及重新分配欄寬屬於同一次可復原操作。既有的分頁及引言容器會保留可編輯的空白行。

游標移到分隔線時會顯示調整控制點。拖曳時只會改變相鄰兩欄，先在目前介面預覽，放開時才一次儲存。按 Escape 取消預覽，按方向鍵可調整分隔線，按兩下可恢復相鄰兩欄等寬。相對欄寬可選擇儲存在起始圍欄中，例如 `::::columns widths=40,60`。未指定時各欄等寬。窄螢幕會將欄垂直堆疊，保留已儲存的比例，並停用從側邊拖放來建立欄。唯讀檢視會隱藏欄寬調整與拖曳建立欄的控制項。

`packages/editor/src/plugins/block-tree.ts` 提供文件修訂版本內的區塊位置、父子關係與原子子樹移動，與 Vue 及儲存層獨立。移動操作會拒絕以自身後代作為目標。最後一個子區塊移出容器時，會留下可編輯的段落。區塊旁的控制點、快顯功能表與拖放目標使用同一棵樹。文件變更後會取消過期的拖曳。Alt+上/下可調整同層區塊的順序，Alt+右可移入前一個容器，Alt+左可移出。也可透過快顯功能表將區塊包入新的可摺疊區塊。展開狀態與使用中的分頁只影響顯示。

## 表格版面

GFM 表格仍以一般 Markdown 儲存。尚未手動調整的表格會平均分配容器寬度，每欄至少 160 px，必要時可水平捲動。容器大小改變時會重新計算自動欄寬，無需儲存版面或建立復原紀錄。拖曳調整欄寬後，表格改用固定的整數 CSS 像素寬度，最小為 48 px。欄寬依穩定的檔案身分另行儲存在 `.tano/document-layout/<fileId>.tano.json`。固定寬度表格的總寬度為各欄寬度之和。只變更顏色的版面透過 `autoWidth: true` 保留自動欄寬。沒有這個旗標的版面會保留已儲存的像素寬度。只修改版面時不會重寫 Markdown。

將游標移到控制項可選取整列或整欄，並插入、複製、清除、刪除，或從色彩子選單分別設定文字與背景顏色。列和欄選單底部有分隔線，下方提供「恢復自動寬度」選項。該選項對整張表格生效，保留原有色彩、對齊方式及 Markdown。若已採用自動寬度，選項會停用。復原操作會精確還原先前的固定欄寬。拖曳控制項可重新排列整列或整欄，並可一次復原。結構調整會保留 GFM 所需的一個標題列及至少一個正文列。儲存格的文字與背景色可選擇以色盤索引矩陣與欄寬一併儲存。寬度及色彩會隨儲存格移動，並與 Markdown 分開儲存。

編輯器中的表格身分在同一工作階段的編輯和移動中會保留。重新開啟或因外部變更重新解析時，必須透過內容及上下文唯一比對表格，才能還原版面。比對不明確或表格有變更時，會使用預設寬度，未配對的紀錄仍會保留。寫入版面時會比較基準雜湊，合併彼此獨立的表格變更，並在 `.tano/conflicts/` 保留有衝突的本機版面。若要一併複製版面，須保留對應的版面資料。

## 專案組織

專案可使用一般工作區資料夾與 Markdown 文件，也可使用內建的 `project` 物件，記錄狀態、目標及到期日。總覽文件和專案物件各有穩定身分，資料夾路徑用於組織檔案。`member` 關係連接人員與專案，`contains` 關係則連接專案與任務、實驗、文件或素材。內容關係不會授予工作區存取權。

專案紀錄位於 `.tano/objects/`，與其他內建紀錄共用建立、屬性編輯、複製、引用及關係管理流程。既有專案檔案、ID 和 `object://project/<id>` 引用可直接沿用，也可繼續編輯舊紀錄。寫入仍須具備工作區權限，且基準雜湊必須相符。任務與事件紀錄、行事曆同步及人員責任關係沿用既有模型。

## 規劃事件

計畫側欄與行事曆共用所選日期。側欄顯示當天的事件和任務，以及尚未排程的任務。新任務和行事曆項目都是位於 `.tano/objects/` 的 `event` 物件，可設定下列屬性。

- `checkable` 表示事件是否需要勾選完成，`completed` 記錄完成狀態。
- `date` 是不指定時段的本機計畫日期，格式為 `YYYY-MM-DD`。可選擇是否追蹤完成狀態，因此也適用於週年紀念和提醒。僅有日期的項目會顯示在行事曆時間格上方，也會出現在月、年及議程檢視中。
- `start` 與 `end` 是一對明確指定時區的時間戳記。指定時段的事件會顯示於行事曆，包括可以勾選完成的事件。

使用 `date` 或 `start` 與 `end` 這對欄位。兩種都未設定、但需要勾選完成的事件，就是未排程的任務。完成或安排事件會更新同一物件，並遵循既有的基準雜湊合併規則。截止日與計畫執行日期分開記錄。Markdown 核取方塊留在原始文件中。

建立與編輯詳細資料共用同一個排程控制項，可選擇未排程、計畫日期或時段。計畫日期與時段都可透過一個文字按鈕切換全天與精確時間，並保留這次編輯中已輸入的日期與時間。精確的單一時刻不會套用預設持續時間，儲存為 `start === end`。全天範圍包含所選的起訖日期，儲存 `allDay: true`，以第一天午夜為 `start`，並以最後一天隔天午夜為不含在範圍內的 `end`。這與行事曆的半開區間一致。完成狀態與日期精度各自獨立。

舊的 `task` 檔案保留原有 ID 和引用網址，可繼續讀取與編輯。它們透過相容層出現在計畫側欄。工作台會將新任務建立為 `event` 物件，建立表單會使用這個統一的類型。

### 個人與工作區歸屬

新的事件和任務可以儲存到個人或工作區。既有紀錄保留工作區歸屬。側欄和行事曆共用「工作區／個人／全部」篩選。「全部」涵蓋個人紀錄及目前工作區的紀錄。來源標籤及複合檢視鍵可區分短 ID 相同的紀錄。完成、排程與詳細資料變更都會寫回原始來源。

工作區紀錄存放在該工作區的 `.tano/objects/`。原生應用程式的個人紀錄位於應用程式資料下獨立的 `personal/.tano/objects/`。可攜身分保存在 `personal/.tano/`，可重建的 `personal-index.sqlite` 位於 `.tano/` 之外。個人檔案屬於應保留的使用者內容。個人紀錄使用獨立的 IPC 與儲存配接器，避免影響目前的工作區工作階段。工作區的引用、搜尋、外掛與匯出只使用工作區資料。可從計畫側欄與行事曆存取個人計畫，包含工作區唯讀或停用物件功能時。

瀏覽器的個人紀錄使用獨立的 `tano.personal-plans.v1` 鍵。寫入需要 Web Locks，並與最新基準雜湊比對，因此只在支援 Web Locks 的瀏覽器開放。原生操作使用程序協調鎖與既有的原子檔案寫入器。兩個配接器都重用物件合併機制，在發生衝突時保留已儲存版本與編輯草稿，也會保留損毀的資料。

個人紀錄屬於目前的裝置或瀏覽器。桌面版可選擇連接行事曆與待辦事項服務，將指定紀錄與外部服務交換。連線設定、憑證與基準資料收存在應用程式資料及作業系統憑證存放區。行事曆與待辦事項分別設定。瀏覽器與行動裝置只支援匯入 iCalendar 檔案。供應商設定、衝突處理及驗證限制請參閱[計畫同步指南](../zh/planning-sync.md)（簡體中文）。負責人篩選及紀錄歸屬目前以單一工作區為限，尚未提供歸屬遷移。人員紀錄用於表示責任關係，與登入帳號分開。工作區紀錄的負責人也不會自動標為目前的使用者。

### Markdown 物件引用

新引用使用 `[[object://person/e82f91]]` 語法，只儲存類型和穩定 ID，由介面解析目前的名稱。輸入 `@` 會開啟物件選擇器。獨立成行的 `![[object://event/282f91]]` 會呈現物件卡片。一般的 `[[document/path]]` 仍是路徑連結。

既有的 `[name](object://type/id)` 連結和 `tano:object-card` 標題仍可讀取，編輯器儲存時會輸出新版語法。從選擇器插入人員提及時，可附加 `<!--tano:mention:occurrence-id-->` 以避免重複派送 Agent 任務。這是提及紀錄的中繼資料。一般身分引用只用於指向物件，程式碼範例一律以原文顯示。
