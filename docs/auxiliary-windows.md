# 共享 JavaScript 的辅助窗口

本文记录 2026-11-15 至 2026-11-16 的辅助窗口迁移架构、原型实测和验收结果。验证基线为 `f641c8102b82eab754e7cb1c653eabb643946032`，实现位于该提交之上的工作树。

## 原理与窗口模型

桌面工作台在主窗口运行一个 Vue 应用和一份 Pinia store。标签窗口和设置窗口由主窗口调用 `window.open` 创建。Vue 通过 Teleport 将组件挂载到辅助窗口，组件直接使用共享状态。

请求 URL 为 `about:blank#tano-aux=<id>&kind=tab|settings`。ID 长度为 1–64，只允许 ASCII 字母、数字和连字符。原生 label 为 `aux-<id>`。主窗口的 `on_new_window` 严格检查 URL，辅助窗口拒绝继续打开新窗口。设置窗口归主窗口所有，保持 owned window 的层级行为。

`about:blank` 继承打开者的源。Windows 上必须调用 Tauri builder 的 `window_features(features)`，使 WebView2 共用 environment。主窗口通过 Rust builder 动态创建，保留原来的尺寸、背景色、无系统边框、初始隐藏和启动就绪显示流程。

辅助窗口也先保持隐藏。管理器建立上下文、设置位置和布局，等待 Vue 更新与首批 stylesheet 加载，再显示并聚焦原生窗口。开发构建验收发现的初始白窗因此有了明确的显示就绪条件。若原生显示失败，已经移入的文档回到主窗口布局。

辅助布局注册前和移除后，窗格使用本窗口的空布局。发布构建验收曾发现，回退到主布局会让两个窗口挂载相同 pane ID 的编辑器，反复改写共享编辑器引用，最终造成渲染循环和 V8 内存耗尽。现已移除辅助窗口的主布局回退，并用注册前、注册后和移除后的组件测试覆盖。修复后的发布可执行文件已成功打开、编辑和保存辅助文档。

`windows/aux-window.ts` 持续镜像样式节点、主题属性、语言和 CSS 变量。发布构建的 stylesheet 使用绝对 href，目标 document 设置源页面的 base URL，资源与字体按应用资源路径解析。开发模式的 Vite 样式新增、删除、属性修改和热更新也会同步。

store 的 `windowLayouts` 以窗口 ID 索引布局和活动窗格。主窗口固定为 `main`。每个标签属于一个窗格，每个窗格属于一个窗口。跨窗口移动只改布局，已有 `OpenDocument`、未保存内容和文件身份保留。会话继续使用原格式，仅写入主窗口的标签、布局和相关恢复草稿。

拖入目标窗口时，DOM dragover/drop 直接调用共享 store 的布局操作。源窗口等待原生释放结果后检查标签归属，防止已经停靠的标签被再次拖出。源、目标窗口用共享响应式拖拽结束状态清理槽位。

## 保存与生命周期

辅助窗口关闭先提交编辑器修改并执行 store 保存，再逐个关闭其标签，最后销毁原生窗口。保存失败会保留窗口并将提示定位到该窗口。原生关闭请求被拦截，Alt+F4 使用相同流程。外部强制销毁后若保存失败，保留 store 内容并重新建立辅助界面。

样式加载期间发生关闭会终止创建等待。创建失败时，仍属于该窗口的标签返回主窗口，包括外部销毁后的界面恢复失败。外部关闭处理等待当前创建任务的恢复完成，避免重复恢复和永久等待。

组件卸载时同时清理 popup 与原生窗口。开发模式热更新曾留下失去页面内容的原生宿主，现已补上显式销毁及卸载回归测试。

最后一个标签关闭或移走会移除该辅助布局，管理器随之销毁空窗口。主窗口关闭先保存，再等待助手与收件箱 settle，关闭辅助窗口，停用编辑器后销毁主窗口。切换或退出工作区先执行辅助窗口关闭流程，保存失败时中止切换。

设置入口默认在当前活动窗口显示悬浮面板，已有设置标签时沿用原有的标签复用行为。点击面板右上角“在新窗口打开”才打开独立设置窗口。独立窗口固定使用 `settings` ID，重复请求聚焦现有窗口，设置页由共享 `settingsPage` 更新。窗口使用 1080×780 的初始尺寸及原有居中算法，按主窗口所在显示器工作区约束位置。

| 路径 | 处理 |
| --- | --- |
| 标题栏、标签栏、窗格、窗口按钮 | 原生操作使用上下文句柄，拖拽和命中测试使用各自 document。 |
| 编辑器、源码编辑器、斜杠菜单、引用选择器、表格控件、公式与图片预览 | DOM 判断使用 realm 安全函数，监听、Selection、浮层、帧调度和观察器使用所属窗口。 |

| 光标、打字、块布局、目录、滚动渐隐和助手蝴蝶动效 | 使用目标元素所在窗口的帧调度或原生元素动画。 |

| i18n、偏好存储、文件监听、插件运行时与 workspace store | 作为应用级共享服务运行一份。原生文件监听持续覆盖辅助窗口正在编辑的工作区。 |
| Markdown 序列化、导出临时 DOM、离屏资源转换 | 使用共享解析或导出环境，生成文档内容后交给相应输出流程。 |
| `file-*`、`print-*` | 保留各自独立入口与原生窗口生命周期。 |

## 标签内容与编辑状态

文档、附件预览、插件视图、工作区视图及设置标签使用统一共享渲染路径，可以移动到辅助窗口。原有因独立应用初始化而设置的标签类型限制已移除。

跨窗口移动会重新挂载目标窗格中的编辑器。文档内容、未保存修改和 store 中的恢复信息保留。收尾检查曾复现撤销历史清空及光标回到开头，现已增加移动前的编辑状态捕获和目标编辑器就绪后的恢复。富文本历史通过公开的撤销、重做命令及 Step JSON 重建到目标 schema，源码模式使用 CodeMirror historyField。光标与滚动位置复用已有视口恢复逻辑。内容或建议修订版本改变时跳过旧历史恢复，避免覆盖新内容。外部修改仍经过现有 base hash、合并和冲突副本流程。

目标窗格较矮时，原本可见的光标会调整到目标可视区域内并保留底部间距。用户主动滚动到光标不可见位置时，继续恢复原有滚动关系。视口与历史的定向测试共 7 项通过，真实弹窗测试也覆盖较矮目标窗口。

## 平台注意事项

macOS 历史上报告过空字符串 `window.open` 被拒绝，本实现显式使用 `about:blank`。该平台仍需要原生验收。[Tauri issue 16425](https://github.com/tauri-apps/tauri/issues/16425)

Windows 历史上报告过 `target="_blank"` 链接无法触发新窗口回调。本实现主动调用 `window.open`。[Tauri issue 15872](https://github.com/tauri-apps/tauri/issues/15872)

Tauri 的 Create 响应要求 WebviewWindow，本实现使用对应 builder。上述 issue 是原型阶段记录的平台背景，当前状态未重新核查。[Tauri issue 16426](https://github.com/tauri-apps/tauri/issues/16426)
