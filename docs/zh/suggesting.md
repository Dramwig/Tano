# 建议编辑

点击文档右上角「更多（⋯）」菜单中的「建议编辑」进入建议模式。顶部助手按钮左侧显示「建议模式」标签，点击标签中的 × 退出；退出不会丢弃待审建议。在建议模式输入、删除或替换内容，会产生待审建议；正式 Markdown 在接受之前保持不变。连续输入合并为同一项，不同位置的修改可以分别接受或拒绝。

新增文字以绿色标记，拟删除文字以删除线展示。右侧卡片显示作者和修改内容，可点击定位，或点击 ✓ 接受、× 拒绝。窄窗口中的卡片排在正文下方。「审阅记录」显示已处理的建议。切回「编辑」显示正式正文；重新进入「建议」可继续查看和修改待审内容。

富文本和源码编辑均支持此模式，撤销与重做作用于当前建议输入。切换模式及接受、拒绝后重建编辑历史，防止旧的撤销记录重新带入已处理建议。建议模式使用渲染后的富文本，不自动展开光标所在位置的 Markdown；需要修改源码时使用右上角源码按钮。

建议模式不重命名文件，不导入新附件，也不持久化表格宽度或单元格颜色。现有附件链接和表格正文可以通过 Markdown 建议修改。复杂结构修改按一次操作作为整体审阅；无法安全映射的富文本修改会提示改用源码模式。当前不提供多人实时网络建议编辑；由外部协作扩展接管的文档暂不启用建议模式。浏览器演示仅保存在此浏览器。

## 助手与外部 MCP 提案

助手中的文档修改提案提供「在文档中逐项审阅」，将修改发布为文档建议。通过 MCP 提交并导入助手的提案使用同一入口。发布后在文档中分别处理；原提案不能再整篇应用，避免把已拒绝的修改重新写入。发布或生成建议不表示正文已经写入。新建文档、工作区事件和关系提案仍使用原有审阅流程。

## 保存与冲突

建议保存在 `.tano/suggestions/<文件短 ID>.tano.json`，绑定工作区和文件身份。文件改名后仍能找到原建议。只复制 Markdown 文件不携带建议；复制工作区时需要保留 `.tano/`。每条记录保存修改基线、范围、替换内容、作者、版本、处理状态及写入凭据；助手聊天记录不作为待审建议的唯一存储位置。

接受时重新读取草稿与磁盘，只应用所选修改。独立的外部修改保留；原文重叠变化、重复内容无法唯一定位或建议重叠时停止应用，保留原文和建议。预览后内容变化时需要审阅更新后的结果再接受。

独立建议可在条件写入冲突后合并。同一条建议被另一位编辑修改或审阅时，不覆盖对方结果；本机内容保留，可以重试，或「另存本机建议副本」后核对。保存失败时阻止正常关闭文档或切换工作区，浏览器关闭会提示存在未保存内容；强制退出进程仍可能丢失尚未成功持久化的输入。

写正文前先保存操作凭据。若正文写入成功但回执未保存，重启后点击「核对写入结果」可核对当前正文与预期结果，不会重复写入。若正文不等于预期结果，保持待核对状态并展示写入前后内容，不自动重放或回滚。此机制不承诺与任意外部文件编辑器之间的绝对原子事务。
