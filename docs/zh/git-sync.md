# 工作区同步与 Git 后端

桌面版从工作区菜单或命令中心进入“Git 与同步”。“变更与历史”直接显示当前分支、文件状态、暂存区/工作区差异和最近提交；“同步设置”管理 Git 或云端后端。全部是系统功能，无需安装、启用或授权插件。旧 Git 变更插件已从内置和社区目录界面移除，已有安装不会加载；原有工作区规则及缓存保留。

## 开始使用

1. 安装 Git 2.38 或更新版本，在 Tano 中打开本地工作区。
2. 在“Git 与同步 → 同步设置”填写 HTTPS、SSH 或本地绝对路径远端，点击“启用 Git 并同步”。没有仓库时初始化 main；已有仓库使用当前分支和 origin，不覆盖已有远端配置。
3. 工作区内已保存且未被 Git 忽略的文件（包括 `.tano/config.json` 和 `.tano/identities.json`）进入提交。提前使用 `.gitignore` 排除不希望同步的文件；不要忽略工作区身份清单。
4. 第二台设备先用 Git 克隆同一仓库，保留整个 `.tano/`，再打开目录并启用同步。独立新建工作区不能通过连接同一远端变成同一身份。

启用后，应用打开期间每 30 秒检查一次，也可立即同步。先保存编辑器内容，再提交磁盘变化、获取远端、预演合并、应用结果并推送。断网时本地提交保留，恢复连接后重试。不强制推送、不重写分支历史，不在退出应用后运行后台服务。系统使用 `Tano Sync` 作为自动提交作者。

SSH 使用系统 SSH 配置和已有认证，禁止交互式口令提示；Windows HTTPS 使用系统 Git Credential Manager 的已有认证。请先在外部 Git 中完成登录。不会把令牌交给插件。其他平台建议使用已配置的 SSH。

## 合并与冲突

- 远端领先时快进；历史分叉时先在 Git 对象库中预演三方合并，成功后保留双亲合并提交。
- `.tano/identities.json` 按稳定身份协调，合并占用 ID；独立分配相同 ID、同名不同身份、身份损坏或空间 UUID 不同都会暂停。
- 普通文件使用 Git 合并规则。重叠编辑或无法自动合并的二进制内容保留两端历史并列出冲突，**不把 Git 冲突标记写进正在使用的工作文件**。此后自动同步暂停，可在外部 Git 中合并 origin 对应分支、解决并提交，再点击立即同步。
- 当前 Git 后端不提供应用内逐块冲突解决器，也未接入云端后端的对象/表格字段级合并；这些 JSON 内容重叠时会安全暂停。
- Git 应用合并时再次检查工作树，不强行覆盖期间发生的外部修改。源文件仍是内容事实源，索引和应用状态不进入工作区。

## 后端互斥与边界

同一工作区同一宿主只启用一个文件同步后端。切换前先停用当前后端；云端文件同步和实时协作活跃时不能启动 Git。云端版本从同一入口进入 Tano 云端配置，原有 HTTP 文件同步能力保留。

Git 同步当前支持根目录中普通 `.git` 仓库；拒绝符号链接、链接工作树、子模块、嵌套仓库、共享对象库和未完成 Git 操作。仓库内自定义过滤器、合并驱动、配置 include 和命令扩展会被拒绝；系统同步不运行仓库钩子。每次 Git 命令最多运行 90 秒。大文件暂未接入 Git LFS，含自定义 LFS 过滤器的仓库需要外部 Git 管理。

每次 Git 操作都有自己的原子性，但“保存、提交、获取、合并、推送”整体不是事务。推送失败不会回滚或删除已经保存的本地提交。
