# 聊天与助手

## 导航与职责

一级导航使用「仓库 / 计划 / 聊天」，「联系人」作为聊天中的分类，与消息和机器人并列。聊天处理人与人的私聊、群聊以及会话中的通知和问答机器人。

未来的 AI 工作台使用独立的「助手」入口。它承载模型对话、工作区上下文、任务执行进度、权限确认、文件差异和结果审阅。普通聊天机器人不因加入会话而获得本地文件或命令执行权限。聊天中可以通过明确的用户动作将一条消息转为助手任务，并把结果引用回原会话。

「助手」尚未实现，因此当前不放置空的一级入口。现有「与 Agent 一起工作」面板继续提供本地 MCP 配置与活动记录。

## 当前实现

- 聊天作为可关闭、可恢复的单一标签页，不会替换正在编辑的文档。
- 消息、联系人、机器人分类支持搜索。示例联系人与会话只在用户选择「先体验示例会话」后载入。
- 添加演示联系人后可进入私聊；选择至少两位联系人可创建演示群聊并查看成员。
- 文本消息仅加入本地演示，显示「仅本地 · 未发送」。各会话独立保留草稿，支持 Enter 提交、Shift Enter 换行与中文输入法确认。
- 机器人只展示用途和未接入状态，不接收消息、不模拟模型回复。
- 联系人、会话、消息和草稿保留在当前工作台实例的内存中，刷新或关闭窗口后清空。关闭聊天标签或切换工作区不会清空本窗口的演示。为了避免跨窗口移动时丢失演示状态，聊天标签暂不支持拖出。

本版没有账号查询、真实好友申请、邀请、消息投递、已读回执或实时通信。浏览器和桌面版都明确显示「本地演示 · 未联网」。

## 后续接入边界

通讯模型与界面位于共享工作台；演示状态与文档存储适配器、编辑器和网络同步分离。真实通讯接入需要替换演示状态层，并通过显式的运行时接口提供账号、好友申请、会话、成员、消息投递状态和订阅生命周期。托管通讯与部署代码留在本仓库之外，遵守[仓库许可范围](license.md)。

真实聊天属于账号层，不以当前工作区路径作为身份，不进入工作区 Markdown 恢复日志。缓存放在应用数据；只有用户明确保存为文档的聊天内容才创建普通 Markdown 文件。引用工作区内容使用工作区 UUID 与稳定对象或文件 ID。

助手执行器须独立于聊天和编辑器，复用[Agent 工作流](agent-workflow.md)的条件写入原则：先读后写并比较基准哈希，合并独立编辑，冲突时保留双方版本，不能越过所选工作区的符号链接边界。任务记录与文件改动审阅不能混同于消息是否投递或已读。
