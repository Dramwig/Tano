# Reliable Sync / Cloud

本地与云端共用 Workspace Contract v1。公共 Core 提供文件身份、对象与数据表 schema、结构化三方合并；账户、网络传输、权限和托管服务由独立 Tano-cloud 仓库实现。纯本地版不内置云服务。

## 内容与身份

Markdown 和附件保持普通文件，对象、关系、属性与视图保持 .tano/ 下的可移植文件。同步按文件 ID 和服务端版本进行条件写入，重命名保留身份；首次下载使用远端 File ID。对象 ID 与源文件 ID 继续独立，文件与对象的修改分别协调。身份清单和本机缓存不作为普通内容上传。双向同步要求两端使用同一个工作区 UUID；独立新建目录不能直接混接。首次从本地创建远端空间会沿用本地 UUID；其他设备应打开携带原 .tano/ 身份文件的工作区副本。独立“拷贝到云端”生成新 UUID，同时转换视图的归属，属于新工作区。旧版本若为同一文件分配了不同的本地/远端 ID，连接会暂停并保留数据，要求先迁移身份映射；不会通过改 ID 或按同名路径猜测来继续同步。同名但不同身份的文件也会暂停，重命名本地占用文件后可继续同步。

对象按属性合并，数据表按行、字段、视图 ID 与单元格合并。Markdown 使用三方文本合并。相同字段的并发修改、删除与修改、不同重命名以及无法解析的结构化内容都保留冲突版本；附件冲突不猜测合并。

空目录使用共享的 `.tano/folders.tano.json` 清单同步。本地仅创建清单中的目录；清单移除目录不会递归删除本地内容，非法路径会被拒绝。

## 离线与恢复

桌面端离线修改先保存普通源文件；应用数据中的持久发送队列记录版本条件、幂等操作 ID 和回执。网络恢复后重新协调，禁止无条件覆盖。正在实时协作的文档暂停普通文件同步，交接状态在重启后仍有效。

浏览器文本、对象和数据表写入前先保存本机恢复记录。断网或结果未确认时，设置中的“修改恢复”可以查看内容、下载副本或重试原修改；这不表示云端已经保存。重试使用原版本条件和操作 ID，云端出现新修改时保留记录并要求人工审阅。浏览器存储不足时拒绝启动发送；清理浏览器数据会删除其中的本机恢复记录。

同步产生的副本全部保存在 .tano/conflicts/。普通文件采用 JSON 恢复封装，含原路径、SHA-256 和 base64 原始字节；内部 JSON 冲突保留完整原文。冲突通知保存到本机同步状态，恢复历史版本仍需比较审阅时的服务端版本。

## 权限与协作

每次远端请求由服务端检查当前权限。离线保存不赋予云端写入权；权限撤销或降级后，拒绝发送并保留本机修改。可移植文件不能赋予账户权限。对象删除和普通文件移动采用稳定 ID、路径和审阅 hash 校验，再由服务端原子版本条件保护。

协作和文件同步使用同一持久文件内容作为最终来源。Yjs 仅用于正在进行的编辑会话，不能替代 Markdown 真源。冲突、副本、未确认写入和部分完成必须可见，跨文件操作不提供整体原子提交。

参见 [Workspace Contract](workspace-contract.md) 和 [云端扩展接口](../cloud-extension.md)。

系统提供统一的“工作区同步”入口，内置 Git 后端；Git 状态、差异和历史也在系统面板中，写入与网络操作由系统管理。见[Git 多端同步](git-sync.md)。
