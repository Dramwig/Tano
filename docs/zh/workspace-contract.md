# Workspace Contract v1

Tano 的工作区由三层组成：**File、Object、View**。三层共享工作区 UUID 和稳定身份，但只有 File 和用户创建的结构化记录保存内容；View 只保存投影规则。

## File

File 是工作区中的真实文件，也是内容事实源。Markdown、PDF、图片、CSV、JSON、代码和其他附件都保留为普通文件。Tano 可以为它们建立索引、预览和引用，但不会把文件正文复制到数据库或 Yjs 二进制中。

每个文件有以下稳定身份：

- `workspaceId`：工作区 UUID；
- `fileId`：`.tano/identities.json` 中分配的六位短 ID；
- `path`：当前展示路径，可随重命名和移动变化；
- `revision.hash`：本次读取的内容 hash。

引用使用 `workspaceId + fileId`，路径只用于显示和打开文件。文件发生外部修改时，写入方必须带上读取时的 hash；hash 不匹配就重新读取、合并或保留冲突，不得静默覆盖。

## Object

Object 是文件之上的稳定语义层，用来表达类型、属性和关系。Object 自身可以是 `.tano/objects/<id>.tano.json` 中的结构化记录，也可以是由工作区文件派生的资源投影，例如 Markdown 文档和图片资产。

Object 不能复制文件正文，也不能把路径当作身份。一个 Object 的引用至少包含 `workspaceId`、`type` 和稳定 `id`；需要写入时还要带对象文件的当前 revision。文档和资产对象由文件索引派生，保存操作应回到原始文件。

协议中的 `object://<workspaceId>/<type>/<id>` 是 Object 的契约身份，用于 API、关系和 View 来源；它不是现有 Markdown 内容中的 `object://<type>/<id>` 引用语法，也不等同于承载 Object 记录的 `.tano/objects/<file-id>.tano.json` 文件身份。宿主适配器负责把契约身份解析到当前对象记录和来源文件。

关系端点使用 `type + id`。关系可以连接文档、资产、事件、人物和插件对象。删除或移动文件不会改变文件 ID；路径变化后，关系仍能回到原文件。

## View

View 是文件和对象的可重建投影，例如文件浏览器、对象列表、数据表、看板和关系图。View 只保存：

- 视图 ID、名称和类型；
- 文件 ID 或对象 `type/id` 来源；
- 筛选、排序、分组和展示设置；
- 可选的非执行查询提示。

View 不保存正文、对象副本或权限。打开视图中的条目时，宿主必须通过稳定 ID 解析当前路径和 revision，并显示来源。跨文件视图定义位于 `.tano/views/`；投影索引可重建，但用户配置应随工作区保留；数据表自身的表格、卡片和看板设置继续随 `.table.json` 用户文件保存。缺少视图时不能影响原始文件和对象。

## Phase 3：对象数据库

`SchemaRegistry` 是对象类型与字段验证的统一入口。内置 Task、Project、Experiment 均为可编辑的独立记录，保存在 `.tano/objects/<id>.tano.json`；已有任务与项目沿用原 ID，不转换为事件。对象创建、更新、归档和删除由工作区 Store 提供，读写仍通过文件适配器进行。

工作区菜单的「创建对象数据库视图」生成 `.tano/views/` 下的 `kind: objects` 定义。`objectDatabase` 保存类型选择、归档范围、筛选、排序、分组、关联目标和 `table / board / gallery` 布局。公共 `ViewEngine` 对当前对象与关系建立同一投影，三种布局消费相同记录；保存或切换布局只改变视图定义，不写入对象副本。空类型选择表示全部类型。

关系 API 使用稳定 `type/id` 端点。`contains` 连接项目与任务、实验或文件对象，`member` 连接人员与项目，`assigned` 支持人员与任务、项目、实验、事件；通用 `related` 关系保留。对象面板可查看双向连接、添加和移除关系，重复添加同一关系不会产生副本。

对象更新按基础版本进行三方合并。独立字段修改可以合并；冲突时保留外部版本，并将本地内容保存到 `.tano/conflicts/`。删除要求工作区身份、File ID 与内容 hash 匹配，原生端移入回收站；过期删除被拒绝。删除对象保留关联边，显示为缺失引用，避免多文件级联删除造成部分丢失。浏览器演示删除使用演示存储，不代表系统回收站。

示例工作区包含「研究对象数据库」，以及通过项目关系连接的任务和实验。可以在三种布局中修改同一记录，并用「关联到」查询相连对象。

## Agent 与权限

人类界面、内置助手和外部 MCP 使用同一套层次：先读取 File 或 Object 的不可变快照，再引用 `fileId` / `objectId` 和 revision 提出修改。Agent 的回答、来源 JSON 和工具结果都是数据，不能扩大读取范围或写入权限。

默认流程是：读取 → 引用来源 → 生成提案 → 显示差异 → 用户采纳 → 条件写入 → 返回新 revision。只有宿主确认写入成功后，界面和 Agent 才能声称已完成。跨文件操作没有事务保证时，必须逐项报告结果。

## 当前示例

可直接打开示例工作区的 [`README.md`](../../examples/workspaces/ai-research/README.md) 查看一份跨格式工作区。它包含 Markdown、PDF、图片、CSV、JSON、Python、数据表、事件对象、关系和一个研究视图。建议按以下顺序体验：

1. 打开 `papers/research-note.md`，通过附件链接回到 PDF、图片和数据文件；
2. 打开工作区对象面板，查看 `AI Research` 事件及其关联文件；
3. 在文件菜单选择「查看文件对象」，确认对象面板中的来源和连接仍使用稳定 ID；
4. 从工作区菜单或命令中心打开 `AI Research 工作台` View，点击来源卡片回到当前文件或对象；
5. 修改 Markdown 或 CSV 后刷新，验证内容仍来自真实文件。

这份示例用于验证 File → Object → View → File 的闭环，不代表 Tano 已经为所有格式提供深度编辑器。当前优先保证真实文件可访问、来源可追溯和冲突可核对。

## Phase 0 / Phase 1 实现边界

### 可迁移数据与可重建索引

| 位置 | 职责 | 是否可以删除重建 |
| --- | --- | --- |
| 用户文件 | Markdown、PDF、图片、CSV、JSON、代码等内容事实源 | 否 |
| `.tano/config.json` | 工作区 UUID 与格式版本，不放缓存或本机会话 | 否 |
| `.tano/identities.json` | 稳定 File ID、路径映射、内容 hash、墓碑与已占用 ID | 否 |
| `.tano/files/<fileId>.tano.json` | 跨格式文件的标签和标量属性；不复制正文 | 否 |
| `.tano/objects/`、关系文件、规则 | 结构化语义、关系、工作区规则 | 否 |
| `.tano/views/` | 共享来源选择与展示定义；不复制来源记录 | 不影响源数据，但删除会丢失用户配置 |
| 应用数据目录 | SQLite 文件索引、搜索索引、本机会话和操作恢复日志 | 索引可重建；待恢复操作与草稿应保留 |

工作区禁止新增 `.workspace/` 或根目录平台数据库。文件属性格式为 `version: 1`、`fileId`、`tags` 和 `properties`；属性值允许字符串、数字、布尔值和 null。属性按 File ID 绑定，路径移动不需要搬迁旁车文件。保存时进行字段级三方合并；同字段竞争写入会保留外部版本，并在 `.tano/conflicts/` 保留本地副本。

### File Registry 与 FileHandler

`Workspace.files` 是存储适配器返回的文件快照；公共 `FileRegistry` 从快照建立 ID / 路径索引，统一提供大小、修改时间、类型、处理程序和内容 revision。注册表不分配身份，也不是新的内容数据库。原生扫描对大文件以流式 SHA-256 生成 revision；不将大小和 mtime 当作写入凭据。尚未提供 hash 的适配器显式保留 unknown revision。

`FileHandlerRegistry` 集中声明格式、预览类型、编辑能力与读取/写入需求。Markdown 和 `.table.json` 继续使用现有编辑器。Phase 1 的 PDF、图片、CSV、JSON 和代码为只读预览：CSV 支持引号、跨行单元格和 TSV；JSON 格式化并显示解析错误；代码高亮只生成文本节点；PDF 使用 PDF.js canvas 分页，不运行文档脚本或嵌入网页。PDF/图片在渲染前验证内容签名；扩展名不授予执行权限。未知格式可导出或在桌面端使用默认应用打开。

为避免大文件阻塞界面，文本预览限 2 MiB，PDF/图片预览限 50 MiB，CSV 展示前 500 行和 100 列；代码超过 100,000 字符回退纯文本。这些是预览限制，不是文件注册或身份限制。CSV/JSON 通用编辑器、PDF 全文搜索与可查询 File Database 不属于本次 Phase 1 预览交付。

### 监听、重扫描与身份恢复

原生适配器监听目录变化，工作台合并事件后重扫描；桌面端另有可见状态下的周期扫描和窗口聚焦恢复。外部原地修改、编辑器原子替换、同卷移动优先通过原生文件身份与路径连续性匹配；唯一内容 hash 为无原生身份或跨卷移动提供后备匹配。相同内容存在多个可能来源时不猜测身份，避免把引用接到错误文件。复制是新文件；ID 不复用。身份清单损坏或丢失时停止写入，不静默重建新的身份。

浏览器演示通过本浏览器存储和 storage 事件模拟变化；写入在共享锁内重新读取持久化值再比较 hash。它不监听操作系统文件夹。云产品继续通过公共适配器提供文件快照与附件读取，服务端同步协议和二进制冲突同步属于后续阶段。

### 验收路径

1. 在真实桌面工作区打开示例，点击 PDF、图片、CSV、JSON、Python 文件检查预览。
2. 在文件右键菜单打开「文件属性」，修改标签与属性，再重命名/移动文件，确认属性和 View 来源保持同一 File ID。
3. 用外部编辑器修改文件，确认预览刷新；在编辑中的 Markdown 或元数据上制造并发修改，确认独立修改合并、冲突双方保留。
4. 保留整个工作区与 `.tano/`，重建应用索引或在另一位置打开副本，确认引用和文件属性仍可解析。
5. 自动化覆盖 `file-core.test.ts`、`file-metadata.test.ts`、`file-preview.test.ts`、工作区监听/冲突测试和原生存储身份测试；运行 `npm run check` 与 `npm run test:native`。

## Phase 2：文件数据库 MVP

在目录（或文件树空白区域）右键选择“以数据库视图管理此目录”，即可为原目录建立动态视图。新增文件会在重扫描后自动进入视图，不导入、不复制、不改写源文件。保存的视图可从工作区视图菜单再次打开。

- `.tano/views/<id>.tano.json` 的 `database` 保存目录相对路径、递归开关、AND 筛选条件、排序和分组。`sources` 可为空；每行来自 File Registry 中的稳定 File ID。目录作用域按路径匹配，文件移出作用域后退出视图；属性与关系仍随 File ID 保留。目录整体重命名后需为新目录建立视图。
- Markdown 的标签与属性直接读取文档 YAML frontmatter，包括 `owner` / `负责人`、`status` / `状态`；通过已有文档属性编辑，数据库仅提供可重建的查询投影，不写第二份属性。非 Markdown 文件的标签及自定义标量属性保存在 `.tano/files/<fileId>.tano.json`，支持筛选、排序、分组。负责人并不自动创建 Person 对象。
- 筛选支持包含、等于、为空，多条件取交集。数字属性按数值排序。标签分组时，一个文件可出现在多个组中；内部 `.tano/` 文件永远不进入数据库结果。
- Markdown 的关联数来自正文内去重的引用（文档链接、双链和对象引用），在正文中编辑引用，不另建关联记录。非 Markdown 文件与对象关联复用 `.tano/relations.tano-relations.json` 的 `related` 边，使用 asset 投影，端点 ID 不依赖路径；此关联功能需要启用 Level 2。历史 Markdown 旁车属性和关系文件保留，但不作为文件数据库中 Markdown 属性或关联数的数据源。
- 视图保存使用打开时的内容哈希进行比较写入；外部版本改变时拒绝覆盖，当前设置另外保存至 `.tano/conflicts/`。属性保存仍按字段合并独立编辑，冲突保留两份。

示例工作区提供“研究文件数据库”，包含论文状态、负责人、标签及已有对象关系。
