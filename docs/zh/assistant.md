# Tano 助手

Tano 助手在文档旁提供问答与修改建议。桌面版支持 API、Codex CLI 和 Claude CLI，不需要 Tano 账号；浏览器演示只生成模拟响应。

## 模型连接

### 本机 CLI

先在终端安装并登录 Codex CLI 或 Claude CLI。进入助手「模型连接」，选择相应连接方式，填写名称并保存，无需在 Tano 中填写 API 密钥。留空路径会从 PATH、Windows 官方 npm 安装及用户 `.local/bin` 查找原生可执行文件；也可指定绝对路径。Windows 的 `.cmd`、`.ps1` 包装器不支持，旧版仅提供 JavaScript 入口的 Claude CLI 须升级。此接入已在 Codex CLI 0.155.1 与 Claude CLI 2.1.278 上验证参数；旧版缺少参数时会提示更新。

在当前对话选择「CLI 默认模型」以沿用 CLI 的模型与供应商配置；Claude 还提供 `sonnet`、`opus`、`haiku` 别名。这里不是服务端模型目录，其他模型仍通过对话中的手动模型入口指定。默认模型可能随 CLI 配置变化。Tano 不保存 CLI 登录凭据；Claude 安全模式下会将用户设置中的供应商凭据与模型环境变量传给子进程，已有进程环境优先，不加载用户工具、hooks 或插件。命令行参数中不包含这些凭据。通过 `apiKeyHelper` 执行命令取密钥的配置暂不支持。

每轮通过非交互 CLI 返回结构化回答和 Tano 工具请求，成功退出并确认本轮完成后才交给原有工具执行器。首版在本轮完成后显示回答，不逐字流式显示；工具结果仍会续轮。CLI 原生终端、文件、网络搜索、MCP、插件及 hooks 通过启动配置禁用；运行目录位于应用数据的临时目录，未将工作区路径交给 CLI。Codex 保留用户供应商配置并逐个关闭配置中发现的 MCP 服务。若组织管理策略强制启用工具或 hooks，不适合此模式，应由管理员先调整策略。临时目录和 CLI 原生会话不会作为 Tano 的正文来源。

停止、关闭窗口或 180 秒超时会终止 CLI；Windows 使用进程组回收子进程。失败、输出超过限制、未授权工具和不完整结构化回答不会执行建议。CLI 仍会使用其已有供应商发送选定内容，计费与权限由该供应商管理。

### API

打开工作区和文档，在文档工具栏点击助手图标，再进入「模型连接」。填写连接名称、API 基础地址和 API 密钥，并选择服务支持的接口协议。例如 OpenAI 的基础地址是 `https://api.openai.com/v1`，不要追加 `/chat/completions` 或 `/responses`。密钥保存到系统凭据库，编辑连接时留空保留原密钥。

回到对话，选择连接及当前对话的模型。模型列表由该连接的 `/models` 接口读取，可刷新；服务未提供列表时，可在对话中手动指定模型 ID。每个会话分别保存连接和模型，重新打开时恢复；切换连接后须重新选择模型，生成期间不能切换。连接被删除时，历史会话保留原选择，须另选连接才能继续。旧会话从最后一条助手消息恢复模型。模型出现在列表中不保证支持当前文本流及工具调用协议。

支持 Responses 和 Chat Completions 文本流与函数工具调用。新连接默认 Responses，旧连接默认 Chat Completions。Responses 发送 `max_output_tokens`、`store: false`，工具续轮回传完整输出及加密推理数据；Chat Completions 发送 `max_completion_tokens` 与 `stream_options.include_usage`。供应商必须支持所选协议及参数；同一服务中的不同模型可能要求不同协议，此时可建立分别使用两种协议的连接。暂不支持 Anthropic 或 Gemini 原生协议。关闭「工具调用与修改建议」后仅提供问答。远程服务须使用 HTTPS；本机 HTTP 地址仅允许 localhost、127.0.0.1 和 ::1。连接不跟随重定向。

真实模型需要可用密钥、模型权限及额度。构建和本机协议验收不表示已完成真实模型质量评估，固定材料及检查流程见[真实模型验收](assistant-evaluation.md)。修改到其他服务主机时，已有密钥不会被自动复用，须重新填写或新增本机无密钥连接。

开发时更新原生助手后须完全退出并重新启动桌面程序，网页刷新只更新前端。助手会检查前后端协议版本，不匹配时停止调用并提示重启，避免旧后端将新连接格式误报为数据损坏。

## 参考内容与讨论

从文档或选区打开助手，查看已选参考文档，再填写任务。参考使用生成时的完整 Markdown 快照，优先包含未保存草稿。选区限制修改范围；无法唯一映射到 Markdown 时，切换源码模式重新选择，或清除选区后提出整篇建议。

默认只读取选定文档。开启「允许检索当前工作区」后，模型可以搜索并按稳定文件 ID 读取普通 Markdown。回答中的来源可打开；来源变化时提示回答基于旧版本。最多读取 20 篇文档，来源及工作区约定总预算为 256 KB。

同时允许检索当前工作区和读取工作区对象后，助手可以按文档或任务的稳定 ID 查询「引用了什么／被谁引用」及引用片段，再读取获准的相关文档。双链从 Markdown 正文和对象描述推导，与界面使用同一查询，不读取其他工作区或个人计划。

批注或讨论中的助手按钮会将讨论和引用片段填入助手输入框，由你发送。生成后点击回复图标，可以填入原讨论的回复草稿；已有草稿不会被覆盖，发布仍由你完成。切换文档或工作区后，旧回复入口失效。

## 审阅与保存

模型提出建议后，点击「查看差异」，再决定「应用修改」或放弃。生成期间可以继续编辑。独立修改进行三方合并；重叠修改停止写入并保留原文和建议。预览后发生变化会重新审阅，条件写入检查失败不会直接覆盖磁盘。

每项建议单独采纳并显示结果，一轮最多 20 项。新文件不能覆盖同名文件，父文件夹须已存在。文档的「撤回内容」会生成反向提案，保留后续独立修改；它不是删除新建文件。回答也可以通过「保存为文档」生成一项新建建议。

若显示「结果待核对」，先核对磁盘与写入前后内容，不自动重放。只有存储回执或核对证据确认后才显示已应用。当前条件写入不能为任意外部进程提供绝对原子 CAS，仍存在最终 hash 检查与文件发布之间的短暂竞争窗口。

工作区启用对象能力后，可允许助手读取工作区对象并建议事件与关系。任务使用可勾选事件，建议保存到 `.tano/objects/`；关系只连接实际可用的工作区目标。助手也可以对已读取任务提出名称、描述、日期和完成状态修改，替换或清除负责人，以及修改或移除已有关系。旧版任务保留原身份和类型。

例如让三项任务改期、依据验收记录建议完成、查找目录相关未完成事项，或结合任务状态与文档生成附依据的周报。读取对象绑定本轮快照；任务字段独立修改可合并，重叠修改或负责人并发变化会阻止保存。预览后变化须重新审阅，最终写入仍比较当前 hash。每项提案单独确认，不自动应用。人物关联到 Cloud 成员账号时，分配才会产生该成员的通知；助手不会创建账号绑定。结构化建议不会进入个人计划或主动发送到外部日历，结构化撤回暂不支持。

改期预览显示原日期和新日期。整理会议行动项时先查询已有任务，区分新增、更新和可能重复；重复候选需要额外确认才能新增。目录进展汇总返回负责人、任务日期、已完成、待处理与逾期分类和原任务链接，未记录的阻塞原因标为「未知」。交付审阅、模板及重复任务见[团队持续工作](team-workflows.md)。

## 外部 MCP 提案

外部 Agent 保留现有四个文档工具，也可使用四个新增工具：

| 工具 | 用途 |
| --- | --- |
| `tano_read_document_identity` | 获取工作区 UUID、稳定文件 ID、正文及 SHA-256；先在 Tano 中打开或刷新工作区 |
| `tano_propose_document` | 提交待审阅建议；更新带 `expectedHash`，新建用 `null`，重试复用同一 `operationId` |
| `tano_get_proposal` | 查询宿主记录的建议结果；提交成功不代表已写入 |
| `tano_read_workspace_rules` | 读取两处已知的工作区规则文件，不开放任意隐藏路径 |

在助手「会话记录」中刷新「外部 MCP 提案」，打开提案即可复用差异、采纳和撤回。外部客户端名称为自报信息，不代表已验证的人员或模型身份。原 `tano_write_document` 和 `tano_create_document` 仍是直接文件工具，并未转成必须经过内置助手审阅。

## 规则、停止与记录

工作区可以使用 `.tano/rules/assistant.md` 保存便携助手约定；已有根目录 `AGENTS.md` 兼容读取。每份规则最多 32 KB，仅能约束风格和流程、收紧权限，不能授权扩大读取、直接保存、执行终端命令或变更服务地址。Tano 不会自动改写已有规则。

停止会取消模型传输并阻止后续工具调用，已形成的建议仍可审阅。正常关闭窗口时会停止生成，等待已开始的文件操作与会话保存完成；重开后恢复已停止状态和已有回答。异常退出后仍在运行的记录显示为中断，不自动重新调用模型。正在提交的文件操作须核对回执，停止不等于回滚。

连接设置、会话、原文快照和提案记录保存在工作区外的应用数据，按工作区 UUID、路径和本机目录身份隔离；密钥在系统凭据库。最终正文仍是普通 Markdown。历史可能包含原文，在「会话记录」中可删除；最多 200 条会话，每条最多 300 条消息。当前没有自动保留期，也不会自动清理待审阅或待核对建议。

Cloud 托管模型、账号配额、协作写入桥接、后台运行与自动应用属于后续路线，见 [AI / LLM 共同工作规划](ai-collaboration.md)。由 Cloud 协作会话管理的文档目前只能问答，不能绕过协作会话直接采纳文件修改。
