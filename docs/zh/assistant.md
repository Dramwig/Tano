# Tano 助手

Tano 助手在文档旁回答问题，并按你的要求直接修改文件或提供建议。桌面版支持 API、Codex CLI 和 Claude CLI，不需要 Tano 账号；浏览器演示只生成模拟响应。

## 模型连接

### 本机 CLI

先在终端安装并登录 Codex CLI 或 Claude CLI。进入助手「模型连接」，选择相应连接方式，填写名称并保存，无需在 Tano 中填写 API 密钥。留空路径会从 PATH、Windows 官方 npm 安装及用户 `.local/bin` 查找原生可执行文件；也可指定绝对路径。Windows 的 `.cmd`、`.ps1` 包装器不支持，旧版仅提供 JavaScript 入口的 Claude CLI 须升级。此接入已在 Codex CLI 0.155.1 与 Claude CLI 2.1.278 上验证参数；旧版缺少参数时会提示更新。

Codex 连接通过所选 CLI 的 `app-server model/list` 接口读取完整模型目录（包含隐藏条目并遍历分页），可在模型菜单中查看全部、搜索和刷新；选中模型后按其实际模型 ID 传给 CLI。选择「CLI 默认模型」则沿用 CLI 的模型与供应商配置，默认模型可能随 CLI 配置变化。Claude 提供 `sonnet`、`opus`、`haiku` 别名；目录之外的模型仍可手动指定。读取 Codex 模型目录不会创建对话或发送文档，取消、关闭窗口或 30 秒超时会终止读取进程；读取失败会显示错误并保留手动模型入口。目录可能来自 CLI 内置或缓存数据，不保证当前账户具有所有模型的调用权限。

Tano 不保存 CLI 登录凭据；Claude 安全模式下会将用户设置中的供应商凭据与模型环境变量传给子进程，已有进程环境优先，不加载用户工具、hooks 或插件。命令行参数中不包含这些凭据。通过 `apiKeyHelper` 执行命令取密钥的配置暂不支持。

使用 Codex 连接时，在聊天输入框底部、模型旁的「推理」菜单选择低、中、高、很高、最高或极高，也可沿用 CLI 设置。选择按当前会话保存，切换或重新打开会话时恢复，生成期间不能更改。首次使用默认「中」，新会话沿用当前选择；旧会话尚未选择时兼容之前保存的连接强度，没有旧设置则沿用 CLI 配置。连接设置中不再提供该选项，也不改写全局 Codex 配置。较低强度通常更快，可用强度由所选模型决定，不支持时由 CLI 返回错误。Claude CLI 与 API 连接不显示此菜单。

Codex 通过 CLI 的 `app-server` 标准输入输出接口创建临时会话，实时显示回答正文，并显示启动、连接模型、思考、生成、重试与核对回答的进度。结构化回答中的 JSON 包装、工具参数和原始推理内容不作为正文展示；只有本轮成功完成、完整回答及工具权限校验通过后，工具请求才交给原有执行器。临时断线会显示重试状态，成功恢复后继续接收；停止或失败会保留已收到的正文，但不会执行未完成的工具请求。Claude 仍通过非交互 CLI 在本轮完成并成功退出后显示回答；工具结果均会续轮。

CLI 原生终端、文件、网络搜索、MCP、插件及 hooks 通过启动配置禁用；运行目录位于应用数据的临时目录，未将工作区路径交给 CLI。Codex 保留用户供应商配置并逐个关闭配置中发现的 MCP 服务。若组织管理策略强制启用工具或 hooks，不适合此模式，应由管理员先调整策略。临时目录和 CLI 原生会话不会作为 Tano 的正文来源。

停止、关闭窗口或 180 秒超时会终止 CLI；Windows 使用进程组回收子进程。失败、输出超过限制、未授权工具和不完整结构化回答不会执行建议。CLI 仍会使用其已有供应商发送选定内容，计费与权限由该供应商管理。

### API

打开工作区和文档，在文档工具栏点击助手图标，再进入「模型连接」。填写连接名称、API 基础地址和 API 密钥，并选择服务支持的接口协议。例如 OpenAI 的基础地址是 `https://api.openai.com/v1`，不要追加 `/chat/completions` 或 `/responses`。密钥保存到系统凭据库，编辑连接时留空保留原密钥。

每条连接右侧的「更多操作」菜单提供「检测连通」与「编辑连接」。API 检测使用已保存的地址和密钥读取模型列表，显示检测结果，不发送文档内容；模型列表可用不代表具有所有模型的调用权限。Codex CLI 检测会读取模型目录，Claude CLI 检测仅确认本机可执行文件可用；登录状态与模型生成能力需在会话中确认。

回到对话，选择连接及当前对话的模型。模型列表由该连接的 `/models` 接口读取，可刷新；服务未提供列表时，可在对话中手动指定模型 ID。每个会话分别保存连接和模型，重新打开时恢复；切换连接后须重新选择模型，生成期间不能切换。连接被删除时，历史会话保留原选择，须另选连接才能继续。旧会话从最后一条助手消息恢复模型。模型出现在列表中不保证支持当前文本流及工具调用协议。

支持 Responses 和 Chat Completions 文本流与函数工具调用。新连接首选 Responses，旧连接首选 Chat Completions。Responses 发送 `max_output_tokens`、`store: false`，工具续轮回传完整输出及加密推理数据；Chat Completions 发送 `max_completion_tokens` 与 `stream_options.include_usage`，并将开头连续的系统消息按原顺序合并为一条，兼容硅基流动等只接受一条开头系统消息的服务，所有指令和工作区约定均保留。暂不支持 Anthropic 或 Gemini 原生协议。关闭「工具调用与文件操作」后仅提供问答。远程服务须使用 HTTPS；本机 HTTP 地址仅允许 localhost、127.0.0.1 和 ::1。连接不跟随重定向。

API 连接默认开启「自动适配接口与参数」，已有连接也默认开启。服务明确报告协议不支持或接口路由不存在时，在同一服务、密钥和模型下尝试另一种协议；明确不支持 Chat Completions 的 `max_completion_tokens` 时改用同值的 `max_tokens`，不支持 `stream_options` 时省略流式用量参数。一次请求最多尝试四次，成功的配置仅缓存在本机进程内并按连接配置、密钥记录和模型隔离，重启后重新协商。工具续轮保持产生工具调用的协议与推理数据；不会删除工具、关闭 `store: false`、取消输出上限或在流式响应中断后重放请求。生成状态会显示适配进度。关闭此选项后严格使用首选协议和标准参数。

HTTP 401/403、模型不存在、上下文超限或额度不足不会触发自动适配，也不会自动更换模型或将文档发送给另一家供应商。失败消息提供「切换模型」与「模型连接」入口。如果服务要求标准 Codex 客户端，可接入已登录的 Codex CLI，使用其已有供应商配置和权限；Tano 不会伪装客户端身份，CLI 接入也不保证供应商已授权。模型列表中的模型不等于当前账户获准调用的模型。

真实模型需要可用密钥、模型权限及额度。构建和本机协议验收不表示已完成真实模型质量评估，固定材料及检查流程见[真实模型验收](assistant-evaluation.md)。修改到其他服务主机时，已有密钥不会被自动复用，须重新填写或新增本机无密钥连接。

开发时更新原生助手后须完全退出并重新启动桌面程序，网页刷新只更新前端。助手会检查前后端协议版本，不匹配时停止调用并提示重启，避免旧后端将新连接格式误报为数据损坏。

## 参考内容与讨论

从文档或选区打开助手，查看已选参考文档，再填写任务。参考使用生成时的完整 Markdown 快照，优先包含未保存草稿。选区限制修改范围；无法唯一映射到 Markdown 时，切换源码模式重新选择，或清除选区后提出整篇建议。

默认使用完整工作区上下文，无需选择访问范围。助手可按任务需要搜索当前工作区并按稳定文件 ID 读取普通 Markdown；添加参考文档可指定关注内容，不限制工作区检索。回答中的来源可打开；来源变化时提示回答基于旧版本。最多读取 20 篇文档，来源及工作区约定总预算为 256 KB。

工作区启用对象能力后，助手也可以按文档或任务的稳定 ID 查询「引用了什么／被谁引用」及引用片段，再读取获准的相关文档。双链从 Markdown 正文和对象描述推导，与界面使用同一查询，不读取其他工作区或个人计划。

批注或讨论中的助手按钮会将讨论和引用片段填入助手输入框，由你发送。生成后点击回复图标，可以填入原讨论的回复草稿；已有草稿不会被覆盖，发布仍由你完成。切换文档或工作区后，旧回复入口失效。

## 执行、审阅与保存

助手根据本次要求判断执行方式。明确要求修改、新建、删除、重命名或移动文件时，助手直接完成操作；只有实际保存成功才显示「已完成」。执行前会保存操作记录，结果不确定时保留「结果待核对」，不会自动重试。普通问答不会修改文件，意图不明确时先澄清；旧建议和外部提案不会自动执行。

在任务中说明「先给建议，不要修改」时，助手会保留修改建议，点击「查看差异」后再决定「应用修改」或放弃。无需手动切换模式，旧会话的模式选择也不再影响执行。生成期间可以继续编辑。独立修改进行三方合并；重叠修改停止写入并保留原文和建议。保存前内容又有变化时会暂停该项操作，条件写入检查失败不会直接覆盖磁盘。

变更清单以实际工具回执为依据，回答中“已完成”等文字不能代替保存记录。没有生成建议的回复会显示「本轮未生成修改建议，未写入文件」；工具调用失败时可以展开「工具执行记录」查看原因。会话会保存简要工具回执，继续对话时把实际建议状态一并提供给模型；旧会话缺少回执时标记为未知，不推断工具已成功。转入文档逐项审阅的建议须在文档中核对，已应用记录也不保证文件此后没有变化。

每轮回复以一份文件变更清单展示操作结果或建议：同一文件的操作按稳定 ID 归为一行，标记新增、修改、删除、重命名或移动；展开后显示内容差异、新旧路径、操作理由与执行结果。任务与关系操作也保留各自入口。直接执行逐项保存并显示结果；修改建议逐项采纳，一轮最多 20 项。新文件不能覆盖同名文件，父文件夹须已存在。文档的「撤回内容」会生成反向修改，直接保存并保留后续独立修改；它不是删除新建文件。回答也可以通过「保存为文档」生成一项新建建议。

删除、重命名和移动仅针对已读取的完整 Markdown 文档，选区不能授权整文件操作。应用前须保存本地草稿，并重新核对文件身份、路径和内容哈希；直接执行时，模型读取后内容或路径已变化会暂停该操作，保留变更供核对后手动应用；手动预览后发生变化也须重新核对。重命名和移动保留稳定文件 ID，不覆盖目标文件，目标父目录须已存在。桌面删除进入回收站，浏览器演示直接移除；这三类操作暂不提供「撤回内容」，删除可通过系统回收站恢复。在线适配器尚未接入这些文件操作时会明确提示不支持。

若显示「结果待核对」，先核对磁盘与写入前后内容，不自动重放。只有存储回执或核对证据确认后才显示已应用。当前条件写入不能为任意外部进程提供绝对原子 CAS，仍存在最终 hash 检查与文件发布之间的短暂竞争窗口。

工作区启用对象能力后，助手可读取工作区对象，并按用户要求操作事件与关系。任务使用可勾选事件，数据保存到 `.tano/objects/`；关系只连接实际可用的工作区目标。助手也可以对已读取任务提出名称、描述、日期和完成状态修改，替换或清除负责人，以及修改或移除已有关系。旧版任务保留原身份和类型。

例如让三项任务改期、依据验收记录建议完成、查找目录相关未完成事项，或结合任务状态与文档生成附依据的周报。读取对象绑定本轮快照；任务字段独立修改可合并，重叠修改或负责人并发变化会阻止保存。预览后变化须重新审阅，最终写入仍比较当前 hash。明确的执行指令会逐项保存，修改建议仍需逐项确认。人物关联到 Cloud 成员账号时，分配才会产生该成员的通知；助手不会创建账号绑定。结构化建议不会进入个人计划或主动发送到外部日历，结构化撤回暂不支持。

改期预览显示原日期和新日期。整理会议行动项时先查询已有任务，区分新增、更新和可能重复；发现重复候选时暂停直接新增，保留建议供核对后确认。目录进展汇总返回负责人、任务日期、已完成、待处理与逾期分类和原任务链接，未记录的阻塞原因标为「未知」。交付审阅、模板及重复任务见[团队持续工作](team-workflows.md)。

## 外部 MCP 提案

外部 Agent 保留现有四个文档工具，也可使用四个新增工具：

| 工具 | 用途 |
| --- | --- |
| `tano_read_document_identity` | 获取工作区 UUID、稳定文件 ID、正文及 SHA-256；先在 Tano 中打开或刷新工作区 |
| `tano_propose_document` | 提交待审阅建议；更新带 `expectedHash`，新建用 `null`，重试复用同一 `operationId` |
| `tano_get_proposal` | 查询宿主记录的建议结果；提交成功不代表已写入 |
| `tano_read_workspace_rules` | 读取两处已知的工作区规则文件，不开放任意隐藏路径 |

在助手「会话记录」中刷新「外部 MCP 提案」，打开提案即可复用差异、采纳和撤回；这些外部提案仍需手动采纳，不会自动写入。外部客户端名称为自报信息，不代表已验证的人员或模型身份。原 `tano_write_document` 和 `tano_create_document` 仍是直接文件工具，并未转成必须经过内置助手审阅。

## 规则、停止与记录

工作区可以使用 `.tano/rules/assistant.md` 保存便携助手约定；已有根目录 `AGENTS.md` 兼容读取。每份规则最多 32 KB，仅能约束风格和流程、收紧权限，不能扩大读取范围或用户授予的执行权限，也不能授权执行终端命令或变更服务地址。Tano 不会自动改写已有规则。

停止会取消模型传输并阻止后续工具调用，已完成的修改保留在变更清单中，已形成的建议仍可审阅。正常关闭窗口时会停止生成，等待已开始的文件操作与会话保存完成；重开后恢复已停止状态和已有回答。异常退出后仍在运行的记录显示为中断，不自动重新调用模型。正在提交的文件操作须核对回执，停止不等于回滚。

连接设置、会话、原文快照和提案记录保存在工作区外的应用数据，按工作区 UUID、路径和本机目录身份隔离；密钥在系统凭据库。最终正文仍是普通 Markdown。历史可能包含原文，在「会话记录」中可删除；最多 200 条会话，每条最多 300 条消息。当前没有自动保留期，也不会自动清理待审阅或待核对建议。

Cloud 托管模型、账号配额、协作写入桥接与后台运行属于后续路线，见 [AI / LLM 共同工作规划](ai-collaboration.md)。由 Cloud 协作会话管理的文档目前只能问答，不能绕过协作会话直接采纳文件修改。
