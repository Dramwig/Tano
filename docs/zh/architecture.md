# 架构

[English](../architecture.md) | 中文 | [日本語](../ja/architecture.md) | [Deutsch](../de/architecture.md) | [文档目录](README.md)

Vue 工作台通过文档 store 使用 `WorkspaceAdapter`。桌面适配器调用由 `tano-native` 实现的 Tauri IPC 命令；浏览器演示使用独立的浏览器存储适配器。`configureWorkbench(pinia, runtime)` 将一个运行时绑定到每个工作台实例。

```text
Vue 工作台 -> 文档 store -> WorkspaceAdapter -> Tauri IPC -> tano-native
```

Markdown 文件是内容的事实源。编辑器与无界面 codec 使用相同的 Markdown schema。编辑器通过 `EditorExtension` 接收宿主功能，使编辑与存储、传输保持分离。

每次保存都对比文件与基线 hash。独立的外部修改可合并；重叠修改则保留双方版本供检查。对不与 Tano 协调的外部进程，最后一次 hash 检查与原子替换之间仍有很短的竞争窗口。

工作区身份与文件路径无关。工作区 UUID、文件短 ID 和 ID 占号随 `.tano/identities.json` 携带。对象、关系和规则也保存在 `.tano/`；SQLite 索引、草稿及会话状态位于工作区外的应用数据中。Tano 不会跟随指向选定工作区外部的符号链接。

## 建议编辑

文档支持[建议编辑](suggesting.md)：正式正文仍为 Markdown，待审修改独立保存在 `.tano/suggestions/<fileId>.tano.json`。工作台生成建议投影，编辑器仅展示插入与删除标记；接受通过文档协调入口读取最新草稿和磁盘、验证修改范围、保存写入意图并条件提交。建议文件按记录 ID 合并独立修改，同一记录的并发修改保留双方，异常写入需根据持久化凭据核对。

## 块树

文档、引用、提示块、折叠块和标签页／分栏的分区分别拥有有序子块。这些容器内部可放置正文、表格、列表、引用、提示块、Toggle 或标签页／分栏，递归嵌套。列表和表格保持原有内部 schema，按整个块移动。Toggle 标题属于节点属性；提示块的 `[!TYPE]` 标记属于容器头，不作为可移动子块，紧接标记的正文会解析为独立子块。持久化仍使用 Markdown：引用和提示块使用 `>` 前缀，折叠块使用配对的 `<details>` / `<summary>`，标签页／分栏使用嵌套容器围栏，无需内容迁移或额外存储。

分栏直接显示为横向排布的块容器。分区标题保留在源码中兼容已有内容，界面不显示标题栏或编辑面板。把块拖到另一块的左／右边缘，显示竖向吸附线；释放后自动创建分栏，在已有分栏中则在目标栏旁新增一栏。顶部和底部仍用于纵向排序。移出或删除最后一个块时清理空栏；只剩一栏时还原成普通纵向块。创建、清理和栏宽分配在同一次可撤销事务中完成，已有标签页和引用容器仍保留可编辑空行。

悬停分割线区域才显示调整柄；拖动只改变相邻两栏，过程中本地预览，松手后一次保存，Esc 取消预览。方向键微调分割线，双击恢复相邻两栏等宽。可选的相对栏宽保存在起始围栏中，例如 `::::columns widths=40,60`；省略时保持等宽。窄屏下各栏纵向排列，保留保存的比例，并停用侧边拖放创建分栏。只读视图隐藏调整控件，并禁止拖放创建分栏。

`packages/editor/src/block-tree.ts` 提供基于当前文档版本的块位置、父子关系及原子子树移动，与 Vue、文件存储分离。移动拒绝以自身后代为目标，最后一个子块移走后保留可编辑空段落。手柄、右键菜单和拖拽目标使用同一棵树；文档变化后取消过期拖拽。Alt+↑/↓ 调整同级顺序，Alt+→ 移入前一个容器，Alt+← 移出当前容器；右键菜单还可将块放入新折叠块。展开状态和当前标签页只属于展示状态。

## 表格布局

独立的[数据表](data-tables.md)用于结构化记录和横向比较，与文档里的 GFM 表格分别建模。数据表是可放在任意仓库目录的 `名称.table.json` 用户文件，与 Markdown 共用文件树和文件操作；每行不生成文档。文件身份独立于路径，表内字段、行和视图也有稳定 ID。纯数据模型与公式解释器、工作台控制器、文件适配器分别处理结构、交互和持久化。条件写入按字段与记录三方合并，冲突副本留在 `.tano/conflicts/`，应用会话保存未写入草稿及文件身份。旧的 `.tano/tables/` 文件迁移前保留原始副本。

GFM 表格保持普通 Markdown 语法。未调整过宽度的表格默认等分所在容器宽度，每列至少 160 px，空间不足时可横向滚动。容器缩放会自动适配，不产生保存记录或撤销步骤。拖动列边界后，表格切换为固定整数 CSS 像素列宽（最小 48 px），按稳定文档身份单独保存在 `.tano/document-layout/<fileId>.tano.json`，总宽度为列宽之和。仅设置颜色的布局通过 `autoWidth: true` 保留自动适配；没有该标记的历史布局继续保留已保存的像素列宽。仅调整布局不会重写 Markdown。

悬浮控制柄支持整行或整列选择，提供插入、复制、清空、删除，以及分为文字颜色和背景颜色两组的颜色子菜单。行、列菜单底部均提供“恢复自动宽度”，用分隔线与行列操作隔开，作用于整张表，不改变颜色、对齐或 Markdown；已使用自动宽度时置灰，撤销可找回恢复前的精确固定列宽。拖动控制柄会在一次可撤销事务中移动行或列。结构操作始终保留 GFM 的单个表头及至少一行正文。可选单元格文字和背景颜色以调色板键值矩阵保存在列宽旁；列宽和颜色随单元格移动，不写入 Markdown。

编辑期间表格身份随内容编辑和移动保留。重新打开或外部重新解析后，布局通过无歧义的表格内容及上下文匹配恢复；无法明确匹配或内容已变化的表格使用默认列宽，未匹配的布局记录保留。布局写入对比基线 hash，合并不同表格的独立修改，并将冲突的本地布局保留在 `.tano/conflicts/` 中。只复制 Markdown 文件不会携带列宽。

## 项目组织

项目可以由工作区中的普通文件夹和 Markdown 文档组织，也可以使用内置 `project` 对象记录状态、目标和截止日期。项目说明文档与项目对象各自使用稳定身份；目录路径只负责组织文件，不作为项目身份或权限边界。`member` 连接人物与项目，`contains` 连接项目与任务、实验、文档或资产；这些内容关系不授予工作区访问权限。

`project` 记录保存在 `.tano/objects/`，与其他内置记录共用对象创建、属性编辑、复制、引用和关系流程。已有项目文件、ID 与 `object://project/<id>` 引用继续使用，不需要迁移，也不因记录创建于旧版本而变为只读。写入仍受工作区权限和基线 hash 保护。任务与事件、日历同步和人物负责关系继续使用现有模型。

## 计划事件

计划侧栏与日历共用选中日期，展示当天的任务与日程，以及未安排的任务。新任务和日历条目统一使用 `.tano/objects/` 中的 `event` 对象，其可选属性为：

- `checkable`：是否需要完成；`completed` 记录完成状态。
- `date`：仅安排日期，使用本地 `YYYY-MM-DD` 格式。无需勾选完成，可用于纪念日或提醒日；日历时间网格顶部单独展示，月、年及日程视图也可查看。
- `start`、`end`：成对的带时区时间戳。具有时间段的事件显示在日历中，也可以同时需要勾选完成。

`date` 与 `start`/`end` 二选一。需要完成、但没有日期或时间段的事件进入「未安排」。勾选完成或安排日期都通过原有基线 hash 合并机制更新同一个对象。截止日期与计划执行日期分别表达。Markdown 待办仍保留在原文档中，不复制为事件记录。

新建和详情共用时间安排控件，提供「未安排 / 计划日期 / 时间段」三个选项。「计划日期」和「时间段」均通过单个文字按钮切换全天事件与精确时间，保留已选日期和本次编辑中填写的时刻。具体时刻没有默认时长，保存为 `start === end`。全天时间段填写开始、结束日期，包含结束当天；保存为 `allDay: true` 和从开始日零点到结束日次日零点的 `start`/`end`，与日历的半开区间约定一致。完成状态与日期粒度独立。

已有 `task` 文件保留原 ID 和引用地址，仍可读取和编辑，并兼容展示在计划侧栏中。工作台新建的任务统一保存为 `event`，创建表单不再提供单独的任务对象类型。

### 个人与工作区归属

新建事件或任务时可选择「个人」或「工作区」。已有事项保持工作区归属，不进行自动迁移。工作区上下文的计划侧栏仅显示当前工作区；主页计划可按「全部 / 个人 / 当前工作区名称」筛选，初始为全部。日历标签保留打开时的范围。「全部」仅表示个人事项与当前已打开工作区事项，不读取或锁定其他最近工作区。来源标签与复合视图键区分不同空间中可能重复的短 ID，完成、改期和详情编辑都写回原来源。

工作区事项继续保存在工作区的 `.tano/objects/`。桌面个人事项保存在应用数据目录的独立 `personal/.tano/objects/` 文件中，其身份文件也位于 `personal/.tano/`；可重建索引位于应用数据目录的 `personal-index.sqlite`。个人文件属于用户内容，不是可丢弃的缓存。个人操作通过独立 IPC 和存储适配器进行，不切换当前工作区，不加入工作区引用、搜索、插件目录或工作区导出。用户可从计划侧栏和日历进入个人计划；工作区只读或关闭对象功能不影响个人事项。

浏览器演示的个人事项使用独立的 `tano.personal-plans.v1` 存储键，每次写入使用 Web Locks 与最新基线 hash；缺少锁支持时拒绝写入。桌面使用进程协调锁与现有文件原子写入机制。两种适配器复用对象合并逻辑，冲突时保留磁盘版本和编辑草稿，不重置损坏数据。

「个人」指本设备或本浏览器的独立空间，不是 Tano 账号私有云。桌面端可配置独立的日历和 Todo 连接，通过第三方服务同步选定事项；账号配置与基线位于应用数据目录，密码和令牌位于系统凭据库。浏览器与移动端当前仅提供 iCalendar 文件导入。接入方式、冲突行为与验证限制见[日历与 Todo 同步](planning-sync.md)。归属与负责人是不同概念；当前没有将人物记录绑定到登录身份，也不将工作区全部事项称作「分配给我」。跨工作区责任筛选和归属迁移尚未提供。
