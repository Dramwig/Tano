# Compilación y publicación

[English](../releases.md) | [简体中文](../zh/releases.md) | [繁體中文](../zh-tw/releases.md) | [日本語](../ja/releases.md) | Español | [Deutsch](../de/releases.md) | [Índice de documentación](README.md)

Las guías de [automatización de versiones del Core](../release-automation.md) y [distribución del Core](../core-distribution.md) (en inglés) detallan la validación local, la creación manual de etiquetas inmutables y la publicación en registros de paquetes.

Ejecuta `npm run desktop:build` para compilar un paquete de escritorio. La compilación desde el código fuente funciona sin cuenta ni clave de firma. De forma predeterminada viene sin un servidor de actualizaciones configurado. En Windows, el instalador NSIS se escribe en `apps/client/src-tauri/target/release/bundle/nsis/`.

**Tano Local** es la versión local de código abierto. La compilación oficial para Windows x64 se inicia manualmente desde una etiqueta pública del Core y lleva una prueba de procedencia de GitHub. El proceso de firma usa Authenticode y las vistas previas sin firmar que se aprueben llevan su propia etiqueta. El instalador se adjunta a la publicación del Core correspondiente. El indicador de última versión y el canal de actualizaciones de Product pertenecen al proceso de publicación de Product. Consulta la guía de [publicación de Local y verificación de descargas](../local-release.md) (en inglés).

El repositorio público permite compilar el producto local completo con licencia MIT. El repositorio privado `Tano-cloud` añade las funciones en línea mediante la [Cloud Extension API](../cloud-extension.md), compila los instaladores oficiales y los publica como archivos adjuntos en las versiones de `Dramwig/Tano`. Los archivos de código fuente que genera GitHub contienen solo este repositorio público con licencia MIT. Los binarios con funciones en la nube se compilan en el repositorio privado.

Usa `npm run version:set -- 0.2.0` para actualizar a la vez los espacios de trabajo de npm del Core, los intervalos de versiones de sus dependencias internas, los archivos de bloqueo de npm y Cargo, la configuración de Tauri y las versiones de los crates de Rust. `npm run version:check` verifica que concuerden y forma parte de `npm run check`. Los paquetes auxiliares del protocolo para Python y Rust se publican con sus propias versiones. La versión oficial de Product se gestiona por separado en `Tano-cloud`.

- **Publicación del Core**. Cuando cambie el contenido del Core que se va a distribuir, valida la nueva versión localmente y crea manualmente la etiqueta inmutable `core-vX.Y.Z`. Publica los cinco paquetes de npm y el crate de Rust con la misma versión y el SHA del commit sin cambios locales. Adjunta `core-registry.json` a la versión del Core en GitHub, deja desmarcada la opción de establecerla como última versión y fija ese manifiesto en `Tano-cloud`. Subir una etiqueta por sí solo no inicia ningún flujo de trabajo.
- **Publicación de Product**. Los cambios exclusivos de Product reutilizan el Core fijado. Para adoptar una versión del Core ya publicada, fija su manifiesto. El repositorio privado establece la versión de Product, verifica la etiqueta y el commit del Core y compila el instalador oficial firmado. El flujo privado crea la etiqueta `vA.B.C` en el commit del Core seleccionado en este repositorio y publica el instalador, la firma, las sumas de comprobación y `latest.json` en la versión de Product. Varias etiquetas de Product pueden apuntar al mismo commit del Core cuando solo cambia la capa privada.
- **Actualizaciones y plataformas**. La aplicación oficial busca actualizaciones en `https://github.com/Dramwig/Tano/releases/latest/download/latest.json`. La versión de Product debe ser pública para permitir la consulta anónima. El flujo privado necesita un token de publicación entre repositorios limitado a `Dramwig/Tano`. Admite Windows x64 y Linux x64, con compilaciones firmadas opcionales para macOS. Antes del primer uso en producción se requieren credenciales para las plataformas y comprobaciones de aceptación nativas.

Los paquetes distribuidos deben incluir los [avisos de terceros](../THIRD_PARTY_NOTICES.md). Si cambias las dependencias, ejecuta `npm run notices:generate` para regenerar los avisos incluidos.
