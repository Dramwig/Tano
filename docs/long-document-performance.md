# 长文档渲染性能

## 实现范围

- 块拖拽和折叠按钮由 `IntersectionObserver` 跟踪可见区域，只挂载视口及缓冲区内的控件。编辑器文档模型完整保留。
- 大文档正文按顶层块虚拟化：视口及缓冲区保留真实节点，其余块保留高度占位。标题和包含标题的容器始终挂载；当前选区覆盖的块、搜索和引用定位目标会挂载。导出和打印使用完整快照。
- 表格自动列宽按编辑器合并为一次事务，避免每张表分别触发全文插件更新；选区变化不再重新安排所有表格布局。
- 目录缓存标题位置，滚动时二分查找；正文、折叠、图片或容器尺寸变化时使缓存失效。
- 自定义滚动条通过尺寸观察维护文档高度，滚动时只更新位置。
- 源码高亮缓存顶层块的解析结果，编辑时重算修改区域及相邻块，校验边界后复用其余结果。确定不会改变语法的文本内部输入直接映射位置。64,000 字符以上使用 Worker，连续版本通常只传修改片段和局部高亮结果；合并或跳过版本使用完整快照恢复基准。Worker 不可用时使用同一增量解析器同步处理。
- 源码已有装饰随修改映射，仅替换重新解析的窗口。外部内容变化保留多处独立修改，以免把中间未变文本的选区和本地撤销一起覆盖。
- 后台高亮改变标题高度后保持阅读位置；卸载富文本编辑器时先停止 DOM 观察和插件，再异步清理 Milkdown 上下文。

源码首次解析、功能策略变化、引用定义变化及无法确认块边界稳定的修改会进行全文解析。单个特别大的段落或列表中涉及语法结构的编辑仍按整个顶层块处理，位置映射成本也随缓存数量增长。富文本首次解析及模型相关插件仍处理全文，标题、占位节点和大范围选区也占用 DOM。图片、公式、Mermaid 密集场景和桌面原生文件读取需要分别测量。

## 测量方法

2026-11-05，本机 Windows、Edge 156.0.4314.58、1280×900、生产构建，无 CPU 限速。每个样本含标题、中文和英文、加粗、斜体、行内代码，每十节另含列表、表格及代码块。

前三轮打开耗时从工作区打开请求开始，到正文末尾标记挂载后再经过两个绘制帧；每次关闭再打开，共三次，取中位数。第四轮因屏幕外正文不再挂载，改为等待完整模型和末尾标题挂载后再经过两个绘制帧，对照构建使用相同条件。滚动持续约 2.2 秒，每个动画帧移动 90 像素，记录帧间隔；这些数值用于同方法比较，**不是物理屏幕 FPS，也不是原生磁盘读取时间**。后台系统负载和 GC 会影响结果。

基线为 `1b3faf4f7451d7bb27b9211aa26ab4e5e470c843`；优化结果来自该基线上的未提交工作区生产构建。脚本会记录当前源码 SHA-256、浏览器版本和样本信息；测量前应先构建对应工作区，不能仅凭 Git HEAD 把未提交修改视为原版。

| --- | --- | --- | --- |
| 153 / 22.5 KB | 114.5 → 65.9 ms | 3.9 → 3.6 ms | 320 → 142 ms |
| 745 / 112 KB | 567.8 → 152.3 ms | 13.5 → 4.6 ms | 312 → 224 ms |
| 2,965 / 450 KB | 3,915 → 871.8 ms | 40.1 → 9.6 ms | 1,057 → 361 ms |
| 7,405 / 1.12 MB | 27,855 → 2,815.4 ms | 139.7 → 21.7 ms | 4,049 → 503 ms |

7,405 行样本的三次打开为 2,746.9–2,955.9 ms；初始块按钮从 3,302 个降为 9 个，正文 DOM 仍保留。源码进入耗时以可编辑内容出现为止，后台高亮可能随后完成。滚动仍可能出现长帧，不能据此宣称所有万行文档均达到 60 FPS。

另测 11,105 行、1.69 MB、150 张表的样本：打开中位数 6,039.6 ms，滚动平均帧间隔 40.0 ms，进入源码 1,991 ms。这是本次优化后的扩展样本，没有对应旧版基线，不能计算提升比例；结果表明正文完整挂载仍有明确上限。原始记录在 `%TEMP%/tano-long-md-verified/over-10000-lines/`。

本次完整生产测量记录在 `%TEMP%/tano-long-md-verified/evidence/`，包括 `results.json`、样本、CPU profile 和截图，浏览器错误为 0。基线记录在 `%TEMP%/tano-long-md-20261104/`；旧脚本记录完四组结果后，最后一次返回富文本超时，以上比较只使用已记录完成的测量。

## 第二轮优化与复测

2026-11-05 继续检查打开过程，发现表格滚动条在每张表写入样式后立即读取尺寸，重复触发全文排版。本轮将所有表格的布局测量、布局写入、滚动条测量和滚动条写入分别批量执行。表格注释切换所需的动画起点也在写入前读取。

同时合并每个块重复的节点装饰，并在块边界稳定时保留未变化块的装饰。多张表的列宽变化只重建对应块，等长文本替换仍更新实际改变的内容。一次同文档开发构建诊断中，布局次数由 214 降至 18，样式重算由 318 降至 22。

随后依次运行上一轮保留的生产构建与本轮生产构建，每个样本各打开三次，继续使用前述方法取中位数。

| 行数 | 上一轮构建本次复测 | 本轮构建 | 本轮三次范围 |
| --- | --- | --- | --- |
| 2,965 | 707.5 ms | 514.2 ms | 495.2–603.4 ms |
| 7,405 | 3,211.6 ms | 1,484.1 ms | 1,431.9–1,693.9 ms |
| 11,105 | 5,976.3 ms | 2,855.7 ms | 2,640.6–2,888.4 ms |

本轮收益主要来自打开过程。7,405 行滚动平均帧间隔为 20.8 → 21.8 ms，11,105 行样本仍有较大波动。正文视图更新和完整 DOM 的排版成本仍需进一步处理。

两组生产测试均无浏览器错误。原始记录、CPU profile 和构建标识保存在 `%TEMP%/tano-long-md-second-final/` 下的 `before/`、`after/` 和 `comparison.json`。其中基准脚本的源码指纹描述运行时的工作区，保留构建的身份以 `comparison.json` 中的构建目录及入口文件摘要为准。

本轮通过 386 项相关单元与编辑器集成测试、34 项浏览器回归、客户端类型检查和生产构建。新增断言覆盖跨多张表的尺寸读写顺序，以及相距较远的属性变更和等长文本编辑后的装饰正确性。

## 第三轮源码增量高亮

2026-11-05 接入 CodeMirror 的修改范围，缓存顶层 Markdown 块及高亮区间。局部解析包含相邻块，并比较前后边界。引用定义作为局部解析上下文保留，定义变化会刷新全文引用。版本跳过、功能策略切换和 Worker 故障均有对应恢复路径。

真实浏览器检查还发现前两轮的 Worker 构建选择了 `decode-named-character-reference` 的 DOM 入口，加载时出现 `document is not defined`，随后回退主线程。前两轮的源码进入耗时包含此回退行为。本轮在 Vite 中指定该依赖的无 DOM 实现，并以真实 Worker 返回、增量请求和零 Worker 错误验证。

解析基准使用 4,001 行 / 182,780 字符与 12,001 行 / 552,780 字符的混合中英文文档，包含标题、加粗及高亮。在文档中部连续插入文字，预热两次后取十次中位数，每次结果均与全文解析比较。

| 行数 | 全文解析 | 增量更新 | 单次重解析字符上限 |
| --- | --- | --- | --- |
| 4,001 | 124.73 ms | 0.72 ms | 378 |
| 12,001 | 500.91 ms | 1.85 ms | 382 |

浏览器使用相同样本，依次运行上一轮生产构建与本轮最终生产构建，在首个正文段落输入八组高亮文字，去掉首次后取中位数。计时期间未同时运行本任务的构建或测试。`输入绘制`从 `beforeinput` 到两个动画帧结束，`高亮呈现`还包含等待高亮元素及两个动画帧，受自动化轮询和页面更新影响。

| 行数 | 输入绘制前 → 后 | 高亮呈现前 → 后 | 本轮 Worker 往返 |
| --- | --- | --- | --- |
| 4,001 | 139.4 → 13.2 ms | 205.8 → 95.2 ms | 2.5 ms |
| 12,001 | 444.7 → 30.8 ms | 655.6 → 263.0 ms | 5.1 ms |

高亮呈现包含请求合并等待、结果传输、装饰更新和阅读位置恢复。纯解析耗时与整次交互耗时分别记录。首次打开、富文本滚动和桌面磁盘读取尚未在本轮重新计时。

64 项相关测试通过，覆盖增量与全文结果对照、250 次确定性混合编辑、跨行代码和公式、嵌套列表、引用定义、CRLF/CR、功能策略、跳过版本和 Worker 失败恢复。另通过 6 项开发浏览器回归、生产构建中的真实 Worker 输入与撤销验证、客户端类型检查和生产构建。

基准脚本、原始结果和截图保存在 `%TEMP%/tano-source-incremental/`，其中 `parser-results.json` 为解析基准，`browser-results.json` 为浏览器记录，`final-dist/` 为受测构建。真实 Worker 回归位于 [源码高亮浏览器测试](../scripts/source-highlight-browser.spec.mjs)。

## 第四轮：修改映射、局部装饰、正文虚拟化及超大块输入

2026-11-05 完成四项调整：

1. 源码外部内容变化先按行区分修改，再细化变化行内的字符差异。普通远端首尾两处修改不会覆盖中间的选区或本地撤销；差异计算有时间和编辑量上限，超限时对相应区域保守替换。
2. Worker 的请求版本与界面已接受的高亮版本分别跟踪。基准一致时只返回局部范围；过期结果被丢弃后，下一次返回完整结果恢复一致性。CodeMirror 的装饰和标题行号使用已有范围树映射并局部更新。
3. 至少 200 个顶层块、60,000 字符的正文启用块虚拟化。保留首批块、视口周围的整块缓冲区及选区，按实测高度和宽度缓存占位尺寸。稀疏显示标记和缓冲区减少滚动事务；未变装饰集合缓存子块查询，避免反复扫描根级装饰；块控件在节点替换后更新定位并复用其余 DOM。Markdown 和完整 ProseMirror 模型始终保留，不改变文件或协作存储格式。
4. 对已解析为普通文本的内部区域，中英文文字、数字和安全空格的输入／删除只映射位置，不重新解析整个段落或列表。转义、实体、链接、分隔符、换行和边界变化保留解析路径，以保证与完整 Markdown 解析一致。

依次测试第三轮保留的生产构建和本轮最终生产构建，环境和样本同前，没有并行运行本任务的构建或测试。完整模型和首屏打开各测三次取中位数。

| 行数 | 打开前 → 后 | 初始正文区域 DOM 节点前 → 后 | 滚动平均帧间隔前 → 后 |
| --- | --- | --- | --- |
| 2,965 | 458.7 → 364.2 ms | 8,989 → 1,528 | 7.1 → 7.6 ms |
| 11,105 | 2,335.9 → 1,968.3 ms | 33,519 → 5,158 | 27.5 → 18.8 ms |

正文虚拟化降低了打开和节点数量成本，但滚动仍有长帧：11,105 行样本的 p95 帧间隔前后均为 41.6 ms，超过 50 ms 的帧由 2 次变为 4 次，最大帧间隔为 521.2 → 500.1 ms。缓冲区切换仍涉及编辑器更新与目录位置刷新，不能据平均值声称滚动已经稳定流畅。中等样本的滚动平均值没有改善。进入源码的单次计时为 277 → 279 ms 和 672 → 633 ms，包含切换时的待处理工作，不据此断言切换性能已经稳定改善。

源码连续输入使用第三轮同样的 8 次输入方法，去掉第一次后取中位数：

| 行数 | 输入到两帧绘制前 → 后 | 高亮呈现前 → 后 | Worker 往返前 → 后 |
| --- | --- | --- | --- |
| 4,001 | 13.3 → 16.6 ms | 96.3 → 102.7 ms | 2.4 → 1.6 ms |
| 12,001 | 31.0 → 22.8 ms | 270.2 → 255.2 ms | 6.8 → 3.1 ms |

12,001 行样本中，一次 Worker 回复由约 12,000 个高亮区间降为 10–16 个。高亮呈现仍包含请求等待、自动化轮询及应用状态更新，不能等同于纯解析时间。

另对一个 210,000 字符的单段落和一个 10,000 项列表连续插入普通文字，预热两次后取六次中位数，每次与全文解析结果对照：段落更新为 9.94 → 0.03 ms，列表为 428.89 → 1.71 ms；本轮两者重解析字符数均为 0。该结果不代表插入分隔符或改变列表结构的耗时。

453 项相关单元与编辑器测试通过，覆盖多处远端修改后的光标／撤销、局部装饰与全文结果对照、装饰缓存映射、Worker 跳过版本恢复等。38 项不同的浏览器用例覆盖块拖拽和多选、跨屏复制、搜索定位、屏幕外更新、表格、缩放、模式切换、源码 Worker 与完整打印快照。客户端类型检查与生产构建通过。协作验证使用编辑器接收外部更新的路径，尚未进行两台客户端联网并发压测；没有进行桌面原生磁盘性能验收。

原始结果、CPU profile、构建入口摘要和最终构建保存在 `%TEMP%/tano-four-optimizations/`，最终富文本记录为 `accepted-rich/results.json`，对照为 `before-rich/results.json`，源码为 `browser-results.json`，超大块为 `large-block-results.json`。`after-rich/` 和 `final-rich/` 是收尾优化前的中间版本，不能作为最终结果。新增回归见 [正文虚拟化浏览器测试](../scripts/rich-viewport-browser.spec.mjs)。

## 复测

先从仓库根目录运行生产构建，在另一个终端启动预览：

```powershell
npm run build
node node_modules/vite/bin/vite.js preview --config apps/client/vite.config.ts --outDir apps/client/dist --host 127.0.0.1 --port 43847
```

使用隔离浏览器会话创建测试文档，不会写入用户已打开的工作区：

```powershell
node scripts/benchmark-long-document.mjs --url http://127.0.0.1:43847 --output "$env:TEMP/tano-long-document"
node scripts/benchmark-long-document.mjs --url http://127.0.0.1:43847 --sizes 1500 --output "$env:TEMP/tano-over-10000-lines"
```

脚本在 Windows 优先使用已安装的 Edge，也可通过 `--executable` 指定浏览器。默认样本为 20、100、400、1,000 节；1,500 节为 11,105 行。功能回归在 [长文档浏览器测试](../scripts/long-document-browser.spec.mjs)，性能测量在 [基准脚本](../scripts/benchmark-long-document.mjs)。
