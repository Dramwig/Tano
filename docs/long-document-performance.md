# 长文档渲染性能

## 实现范围

- 块拖拽和折叠按钮由 `IntersectionObserver` 跟踪可见区域，只挂载视口及缓冲区内的控件。编辑器文档模型完整保留。
- 块按钮和表格行列控件按正文坐标定位，普通纵向滚动随内容自然移动。可见范围改变时，普通顶层块只测量新增控件；布局、文档或横向滚动变化仍刷新位置，菜单和拖拽保留跟踪更新。
- 大文档正文按顶层块虚拟化：视口及缓冲区保留真实节点，其余块保留高度占位。标题和包含标题的容器始终挂载；当前选区覆盖的块、搜索和引用定位目标会挂载。导出和打印使用完整快照。
- 表格自动列宽按编辑器合并为一次事务，避免每张表分别触发全文插件更新；选区变化不再重新安排所有表格布局。
- 目录缓存标题位置，滚动时二分查找；正文、折叠、图片或容器尺寸变化时使缓存失效。
- 自定义滚动条通过尺寸观察维护文档高度，滚动时只更新位置。
- 源码高亮缓存顶层块的解析结果，编辑时重算修改区域及相邻块，校验边界后复用其余结果。确定不会改变语法的文本内部输入直接映射位置。64,000 字符以上使用 Worker，连续版本通常只传修改片段和局部高亮结果；合并或跳过版本使用完整快照恢复基准。Worker 不可用时使用同一增量解析器同步处理。
- 源码已有装饰随修改映射，仅替换重新解析的窗口。外部内容变化保留多处独立修改，以免把中间未变文本的选区和本地撤销一起覆盖。
- 后台高亮改变标题高度后保持阅读位置；卸载富文本编辑器时先停止 DOM 观察和插件，再异步清理 Milkdown 上下文。

源码首次解析、功能策略变化、引用定义变化及无法确认块边界稳定的修改会进行全文解析。单个特别大的段落或列表中涉及语法结构的编辑仍按整个顶层块处理，位置映射成本也随缓存数量增长。富文本首次解析及模型相关插件仍处理全文，标题、占位节点和大范围选区也占用 DOM。图片、公式、Mermaid 密集场景和桌面原生文件读取需要分别测量。

## 280 Hz 下的滚动帧间隔测量

2026-11-06 通过 Windows 只读显示查询确认，正在运行的 Tano 窗口位于 `DISPLAY1`，2560×1440、280 Hz，对应约 3.57 ms 的刷新周期。只统计超过 50 ms 的长帧不足以判断这台设备的滚动是否平稳。上一节带 16 ms 定时等待的往返滚动也不能用于估算高刷帧率。

本轮将当时的未提交源码复制到临时目录，构建固定的生产前端，避免开发服务热更新影响结果。使用 Playwright、Edge 156.0.4314.58、无界面隔离会话、1440×1080、无 CPU 限速。静态正文对照实测约 280 次动画回调／秒。主测量由 CDP `Input.synthesizeScrollGesture` 发起浏览器原生鼠标滚动，不逐帧发送自动化命令，也不在测量回调中写入 `scrollTop`；只统计首尾滚动事件之间的动画回调。每组等待加载、先测空闲，再连续测三轮，各采样 2.5 秒，实际滚动窗口约 2.1 秒。

下表取三轮各项指标的中位数。估计缺失刷新槽位为每个间隔的 `max(0, round(间隔 / 3.57 ms) - 1)` 之和，占已回调次数与缺失槽位之和的比例。它是动画回调节奏的估计，**不是显卡实际呈现的掉帧计数，也不是桌面 WebView2 的最终呈现 FPS**。

| 样本 | 动画回调／秒 | 估计缺失刷新槽位 | p95 帧间隔 |
| --- | --- | --- | --- |
| 静态正文对照 | 280.0 | 0.0% | 3.7 ms |
| 普通富文本，30 段 | 272.5 | 2.7% | 3.7 ms |
| 反馈中的 4,432 字节、两张表格原文 | 227.7 | 18.7% | 7.2 ms |
| 长富文本，1,000 段 | 217.8 | 22.2% | 7.2 ms |
| 普通文章源码模式 | 278.6 | 0.5% | 3.7 ms |
| 设置页，后台为普通文章 | 279.5 | 0.2% | 3.7 ms |

三轮最大回调间隔不能被中位数掩盖：普通正文为 43.0 ms、表格原文为 46.4 ms；长文档、源码、设置页首轮分别出现 139.2、164.3、164.2 ms 的回调空隙。这些空隙尚未归因到应用阻塞任务。后两轮源码与设置页接近 280 次回调／秒，不据此宣称首次滚动没有问题，也不据这些样本推断所有页面都以相同程度掉帧。

独立的 CPU profile 与排版时间线将富文本的主要额外开销定位到块侧拖拽／折叠控件的布局测量，以及目录定位读取几何边界时触发的样式与排版刷新。块控件目前在 `window` 捕获滚动事件，其他滚动区域也会安排它的布局任务。在同一临时源码副本中，仅移除这一个全局滚动监听后另建对照，表格原文回调速率为 227.7 → 246.1，长文档为 217.8 → 243.8；普通正文为 272.5 → 274.3。长文档对照的 p95 反而为 7.2 → 10.7 ms，仍有首轮长停顿，因此这项对照只能说明它贡献了部分成本，不能作为完成优化的证据。禁用监听仅用于隔离诊断，没有应用到正式编辑器源码。

最终主测量与对照均无浏览器错误。原始逐帧结果在 `%TEMP%/tano-scroll-fps-20261106-1793897642897/accepted-wheel/results.json`，诊断对照在 `ablation-wheel/results.json`，独立 profile 和时间线在 `accepted-profiles/`；`source.json` 保存源码指纹，`dist/` 为受测构建。早期 `wheel/` 与 `profiles/` 含测量脚本在沙箱预览帧访问 `localStorage` 的错误，不作为最终结果。测量脚本已将偏好初始化限制在顶层页面。

复测使用 [滚动帧间隔测量脚本](../scripts/bench/benchmark-scroll-frame-pacing.mjs)，先按下节启动对应生产构建预览，再运行：

```powershell
node scripts/bench/benchmark-scroll-frame-pacing.mjs --url http://127.0.0.1:43847 --output "$env:TEMP/tano-frame-pacing" --hz 280 --seconds 2.5 --rounds 3
```

`--qa` 可指定反馈原文，默认使用仓库 QA 文档；`--profile` 在计时样本之外另跑一轮并保存 CPU profile 和排版时间线。`--input raf` 是主动逐帧修改滚动位置的压力对照，不应与默认原生滚动结果混用。脚本不打开用户工作区，不修改用户原文，不操作现有桌面窗口。

## 滚动路径优化

2026-11-06 继续对照源码和时间线，确认局部渲染仍有效：1,000 段样本首屏有 971 个正文占位节点。正文虚拟化门槛仍为至少 200 个顶层块且至少 60,000 字符，反馈中的短文不走这条路径。局部渲染减少正文 DOM，不能自动消除辅助控件每帧测量和样式更新的成本。

本轮改动：

- 块侧控件使用现有的正文相对坐标随内容移动。支持 `IntersectionObserver` 的浏览器不再为每次全局滚动安排完整控件布局；进入缓冲区的控件立即就位，普通顶层块只测量新增按钮。嵌套容器和列布局保留完整刷新，以维持相互依赖的边距。无观察器的兼容路径只响应编辑器祖先的滚动。
- 表格插入点、行列抓手、选中轮廓和拖拽标记由窗口固定坐标改为正文相对坐标，滚动区域负责垂直裁切。普通纵向滚动不再重排这些控件；横向滚动、窗口／文档布局变化、打开的菜单和拖拽仍更新定位。菜单继续使用窗口坐标，保持溢出显示和自动避让。
- 目录按滚动内容坐标缓存标题位置，普通滚动只做二分查找。滚动位置和封面避让位置在事件阶段读取，动画回调使用快照，避免在其他组件改样式之后再读取几何值；即使 `scrollTop` getter 也可能刷新尚未完成的布局。

这些调整处理的是滚动更新频率和读写顺序，而不是降低虚拟化门槛或减少文档内容。对应机制见 [Chrome 关于避免同步排版和布局反复刷新的说明](https://web.dev/articles/avoid-large-complex-layouts-and-layout-thrashing)。

本轮继续使用上一节的固定源码副本作为基线，新构建只覆盖本次编辑器、目录及相关表格控件样式；`App.vue` 和共享样式仅覆盖相关区段，其他并行开发不混入性能对照。最终受测构建和记录位于 `%TEMP%/tano-scroll-optimization-20261106-1793902788069/`，`source.json` 记录基线和覆盖文件摘要，`overlay/` 保存实际受测修改，`dist/` 为优化后的构建，`comparison.json` 记录基线来源和构建入口摘要。

最终复测使用 `verified-before/results.json` 和 `verified-after/results.json`。基线文件复制自 `tano-scroll-optimization-20261106-1793901815326/verified-before/`，仍是同一保留构建；最终源码补充内层滚动和列菜单边界兼容后重新构建并复测。采样开始通过 CDP Runtime binding 通知，不再在采样已经开始后用动画帧轮询等待；每轮另存宿主 CPU 负载。参数和计算方法同前，三轮中位数如下。

| 样本 | 动画回调／秒前 → 后 | 估计缺失刷新槽位前 → 后 | p95 帧间隔前 → 后 |
| --- | --- | --- | --- |
| 普通富文本 | 276.7 → 278.1 | 1.2% → 0.7% | 3.7 → 3.7 ms |
| 反馈中的两张表格原文 | 247.4 → 279.0 | 11.6% → 0.3% | 7.1 → 3.7 ms |
| 1,000 段长富文本 | 236.8 → 253.6 | 15.4% → 9.4% | 7.2 → 7.1 ms |

宿主后台负载各轮约 41%–55%，因此绝对数值仍会波动，不能只凭单轮平均值声称已经稳定达到 280 Hz。短表格的持续滚动已接近静态对照，长文档仍有可见区切换和排版成本，p95 尚未达到每个刷新周期以内。新旧样本均无浏览器错误；这些指标仍是浏览器动画回调节奏，不是桌面最终呈现 FPS。

前一固定滚动实现的独立记录在 `tano-scroll-optimization-20261106-1793901815326/cold-profiles/`，直接记录首次原生滚动，不安装帧采样循环；其中长文档、源码和设置页没有记录到超过 50 ms 的执行任务。帧采样中的首轮大间隔尚不能直接归因于应用阻塞，更不能作为桌面最终呈现掉帧的证据。

44 项相关单元和编辑器集成测试、客户端类型检查通过。浏览器验证覆盖块多选／拖拽、虚拟化、折叠、模式切换、完整打印、目录在滚动与换行后定位、短表格滚动和变窄后的按钮对齐，以及滚动后的行列拖动、菜单和撤销。
