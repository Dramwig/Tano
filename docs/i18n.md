# 界面语言

桌面和网页工作台支持简体中文、English、繁體中文、日本語、Español 和 Deutsch，共六种语言。首次启动且没有保存偏好时按系统语言匹配：`zh-TW`、`zh-HK`、`zh-MO`、`zh-Hant` 使用繁中，英文、日文、西语和德语按语言前缀匹配，其余回退简中。已保存的选择优先。在「设置 → 外观设置 → 界面语言」切换后生效，独立设置窗口与主窗口同步。

语言偏好保存在应用 WebView 的 `localStorage`（`tano.preference.locale`），属于当前设备的应用状态，不写入工作区。切换语言不翻译文档正文、文件名、工作区名称、用户模板或插件提供的内容。

## 开发约定

- 页面文案通过 `packages/workbench/src/i18n.ts` 的 `t()` 获取，以中文原文作为键，英文写入 `locales/en-US.ts`，繁中、日、西、德对应 `locales/{zh-TW,ja-JP,es-ES,de-DE}.json`。新增键需同步所有词库；运行 `multilingual-catalog.test.ts` 检查键和占位符。
- 动态值使用 `{0}`、`{1}` 等占位符，并通过第二个数组参数传入。不要将用户内容作为翻译键。
- 需要即时切换的数组标签使用 `computed` 或 getter，避免在组件初始化时固定语言。
- 协议类型、存储字段和标识符保持原值，只在展示边界翻译标签。
- 图标英文标签通过 `node scripts/build-ui-icon-labels.mjs` 生成，使用 `--check` 检查一致性。
- `locale-registry.ts` 是语言注册入口，集中定义选项、助手语言名称、独立启动恢复文案，以及 UI、图标、助手和复数词库加载函数。新增语言只添加一条完整注册记录及其资源文件；`multilingual-catalog.test.ts` 遍历注册表验证资源、键与占位符。
- 主机在挂载任何窗口前等待 `initializeUiLocale()`，加载当前语言和英文回退。`t()` 保持同步；切换先加载再更新语言及设备偏好。快速切换时只应用最后一次选择，加载失败保留原语言并允许重试。已加载的词库缓存在内存中，助手任务仍可使用发起时的语言。中英文的小型助手回退词库保留同步可用，其余助手词库按需加载。
- 日期和数字格式传入 `uiLocale`；脚本中使用 `uiLocale.value`。数量文案在 `locales/plurals-*.json` 中提供 `Intl.PluralRules` 分类，`count` 指定对应的占位符序号；多数量句子使用如 `one-other` 的组合分类，`other` 为回退。目前覆盖条目、文档、页面和导入结果等计数文案；新计数文案需补相应分类。
- 有歧义的短词可以使用 `场景::原文` 键，例如 `推理强度::高`。简中仅显示 `::` 后的原文，其他词库按完整键翻译，无需整体迁移键名。
- `npm run i18n:check` 使用 Vue/TypeScript 语法树检查工作台、客户端和共享编辑器模板文字、属性和表达式中的未翻译中文，检查字面量翻译键缺失及动态模板键。共享编辑器通过宿主传入的 `translate` 翻译自身标签，正文、属性名和属性值保持原样，内部焦点定位使用稳定的结构选择器。`npm run i18n:audit` 输出双向审计 JSON，含可能不再使用的键；动态数据标签仍需人工确认，不自动删除。Markdown 示例正文不作为界面标签翻译；其他有意保留的内容须在紧邻节点的 `i18n-ignore:` 注释中写明理由。

开发时可运行 `npm test -- packages/workbench/src/i18n.test.ts packages/workbench/src/i18n-catalog.test.ts packages/workbench/src/multilingual-catalog.test.ts packages/workbench/src/assistant/language.test.ts` 验证词库和语言行为；`npm run check` 验证完整项目；运行 `npx playwright test locale-browser.spec.mjs` 验证页面切换、语言保存与文档内容保护。

本阶段覆盖共享工作台、设置、编辑器展示标签、图标搜索、日历日期和助手界面。原生系统对话框遵循操作系统语言；外部服务原始错误和第三方插件内容不自动翻译。

六种界面语言使用本地资源，不在运行时请求翻译服务。UI 与图标词库按语言拆为独立构建资源。繁中初稿经 OpenCC 的 `s2twp` 转换，使用軟體、檔案、儲存等词汇；日、西、德以英文为基础生成初稿，并校正常用操作与助手入口。德语操作标签使用简洁的不定式短语；长篇说明仍需持续母语校对，不能将机器初稿视为完整人工审校。`startup-copy.ts` 从注册表取得独立恢复文案，不依赖 Vue 或主词库成功加载。日文与繁中界面使用区域字体回退；用户编辑字体选项保持生效。根目录 README 提供上述六种语言，技术文档的翻译范围与界面语言独立。

## AI 提示词与输出语言

AI 的内置任务提示词、评论回复指令、来源数据说明和语言策略统一使用英文，集中维护在 `packages/workbench/src/assistant/task-prompts.json`。界面按钮、生成进度、工具展示名称及浏览器模拟响应使用 `assistant/locales/` 下对应六种语言的 JSON。系统的工具契约、权限约束和文件操作规则保留一份，通过 `assistantSystemMessages()` 组合当前任务的语言策略，不需要复制两套执行逻辑。

- 普通回答、总结、澄清问题及选项、操作原因的语言优先级为：用户明确指定的语言 → 用户当前自由输入的语言 → 发起任务时的界面语言。判断输入语言时排除引文、文档、历史、代码和工具说明；混合输入以请求主体语言为准，无法判断时使用界面语言。
- 语言策略本身也用英文描述，例如 `The fallback response language for this task is Simplified Chinese (UI locale: zh-CN).`。中文界面的快捷按钮保持中文，点击后填入统一的英文任务提示词。快捷任务、开始草稿和评论回复入口通过 `setBuiltInPrompt()` 标记来源，英文模板不算用户自由输入，因此默认回复界面语言。用户编辑模板后按自由输入处理；手动输入的请求按原文发送。
- 模式提示词也统一使用英文，位于 `task-prompts.json` 的 `modes.inline` 和 `modes.sidebar`。每次请求只添加当前模式：行内模式处理一次任务、简短回复，缺少信息时说明需要补充什么并引导进入侧栏；侧栏模式支持多轮对话和逐项审阅，仅在实际提供 `ask_user` 时要求调用提问表单，否则用普通文本提问。两种模式共用输出语言策略。
- 润色、纠错、续写和局部编辑保留原文语言；混合语言内容保留各部分的语言。界面提供「翻译这篇笔记」单一入口，不展开语言选项，由模型结合笔记内容与对话上下文判断目标语言；用户明确指定目标语言时优先遵循。不要仅凭界面语言决定翻译方向，仅在无法合理判断时澄清。
- 发起任务时固定语言，覆盖参考内容加载、工具调用、等待用户回答和后续轮次。任务中切换界面语言只影响下一次发起的任务。
- 用户输入、文档内容、历史会话和工作区规则按原文传递。评论引用和讨论内容作为 JSON 数据附加，不进行自动翻译。
- 工具名称、JSON 字段、枚举值、文件路径、对象 ID 和 `[来源:S1]` 引用标记保持协议规定的值。传输层继续接收标准消息和工具，无需新增后端协议字段。
- 原生 CLI 包装指令遵循同一优先级，区分用户输入和内置模板。真实 API 语言验收可运行 `scripts/assistant-locale-live.mjs`：设置外部证据目录 `TANO_LOCALE_EVAL_OUTPUT`，先用 `--list` 查看可用模型，再设置 `TANO_LOCALE_EVAL_MODEL` 执行；它使用已配置连接及服务额度，仅发送合成文档，不写入文档或会话。输出保留请求和回复，供逐项核对语言及模式行为。

`assistant/language.test.ts` 检查语言策略，`multilingual-catalog.test.ts` 检查六语 JSON 的键与占位符一致性；提示词、会话、面板及模拟传输测试覆盖语言切换和内容保护。这些检查验证请求与界面行为，真实模型是否遵循输出语言仍取决于所选模型的指令遵循能力。

## 执行过程与最终回答

助手按「流式说明 → 完整校验响应 → 执行工具或继续请求 → 最终回答」循环工作。文本阶段和整次任务状态独立记录：过程消息可以没有工具调用，单次响应结束也不代表任务结束。执行或等待用户回答时过程保持展开；执行器收到最终回答且工具、提问均已结束后，才记录完成并自动折叠过程。正文保留最终回答，可随时展开过程。这里展示面向用户的工作说明和真实执行记录，不要求模型提供内部推理全文。

原生 `phase` 的 `commentary` / `partial_answer` 表示过程，`final_answer` 表示最终回答；`end_turn: false` 要求继续。工具调用始终要求先处理回执。普通 Chat Completions 或 CLI 适配使用英文系统提示词中的兼容协议：每条文本以 `[[tano:progress]]` 或 `[[tano:final]]` 加换行开头，展示时移除标记，原生阶段优先。没有任何阶段信号的旧服务保留兼容行为：完整响应正常结束、没有工具且正文非空时视为最终回答。不会根据“我先看看”等自然语言猜测阶段；不支持或不遵循标记的模型仍有这一兼容限制。

过程消息会连同原生 Responses 输出项回传下一轮，不额外请求一次总结。最多执行 8 轮请求，连续 3 轮没有工具且只返回过程时停止。输出截断、空回答、断流、取消或达到上限均不会标记成功。异常结束摘要按真实工具回执和当前提案状态列出已保存、待审阅及待核对操作；不完整文字保留在过程区。恢复会话时，原先执行中或等待回答的任务标为中断，不自动重放工具。

会话的可选 `activity` 字段记录文本阶段、范围与工具回执、提问的关联，`state` 记录任务状态，`termination.reason` 记录执行器确认的结束原因；旧会话保持可读。复制、保存回答、填写评论草稿及行内结果仅使用最终回答，执行过程仍保留在会话中。`npx playwright test assistant-activity-browser.spec.mjs` 验证中英文过程展开、自动折叠、等待、异常摘要和重载恢复。
