# Git 与版本历史

同页的本地 Git 能力服务于“在文件旁边看清楚改动”。桌面端通过受控的只读 Git 查询显示当前分支、工作区/暂存区状态、单文件差异和最近提交；查询不会提交、暂存、重置、推送，也不会读取远端凭据。工作区文件仍是正文唯一来源，`.git` 仍由 Git 管理，Tano 不把 Git 对象复制进工作区。

当前能力由 `git-inspector` 插件提供。它只在本地桌面仓库根目录可用，网页演示、移动端和云端工作区不会假装拥有本机 Git。云端可以复用同一个状态模型（路径、索引状态、工作区状态、提交摘要），但服务器不能直接读取用户电脑的 `.git`。要支持云端 Git，需要在服务端托管仓库对象、处理权限和凭据、定义分支/并发/推送策略，并为每次同步建立明确的提交身份；这已经是代码托管能力，复杂度和安全责任都高于现有同步服务。

### 在界面中打开

在桌面端打开包含 `.git` 目录的仓库根目录，然后进入「插件 → 发现」，安装「Git 变更」。在插件详情中点击「授权此版本运行」，再从左侧「扩展」（插件工作台）选择「Git 变更」，或从命令中心运行「打开 Git 变更」。该插件已随前端内置，无需另外打包或下载。

页面显示当前分支、文件变更、暂存区与工作区差异，以及最近 30 条提交。刷新读取磁盘上已保存的文件。浏览器演示、移动端和在线工作区没有本机 Git 提供方，授权也不会启用本机查询。

因此建议分开两类历史：

- 本地 Git 历史：保留真实提交、分支和差异，适合开发者工作区；同页只读展示。
- 同页版本历史：记录跨设备同步、外部编辑和冲突的内容快照，适合文档恢复和审计。它可以使用内容寻址对象存储实现，不应强行伪装成 Git 提交。

云服务可以先提供同页版本历史，再增加“导出/导入 Git”或连接外部 Git 托管。只有确定需要云端分支、合并请求和远端推送时，才值得让服务器成为 Git 仓库；不要把同步快照直接改造成 Git，因为删除、重命名、权限、冲突和提交身份的语义并不相同。
